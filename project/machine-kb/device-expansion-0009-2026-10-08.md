## Complete-file storage

The complete claims projection now exceeds the ordinary Git file-size limit. `knowledge/claims/claims.jsonl` and the growing maintainer input `knowledge/inputs/claim-records.json` use Git LFS transport, without rewriting history. Hydrated paths, schema/format versions, full bytes and stable identities are preserved. The existing files were fingerprinted before conversion and passed a byte-identical offline clean/smudge round-trip. No billing or payment settings were changed.

CI hydrates LFS files at checkout. Build, validation and diff-impact tools reject unhydrated pointers with an explicit recovery instruction, and never fetch data themselves. Consumers can retrieve full individual files or use an LFS-enabled checkout, then verify the existing full-content manifest hashes and consume them offline without a language/runtime dependency. GitHub source archives are not assumed complete: inclusion of LFS objects has not been verified because the browser settings page requires a signed-in session. This limitation is documented in the consumer instructions.
