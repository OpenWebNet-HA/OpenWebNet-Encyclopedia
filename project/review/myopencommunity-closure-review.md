## Controlled helper execution

The [reproducer](checks/check_myopencommunity_closure_helpers.py) reads exact preserved Git files and writes only to an external scratch directory. Twelve unchanged original files have retained Git blobs and SHA-256 fingerprints. Native Qt 5.15.19 Core/Xml and C++17 compile the original generic worker, XML serializer, message helpers and PlantMessage implementation. The event handler records GUI requests; class-name and bus-list dependencies are substitutes used only by serialization.

The original `GenMsgWorker::run` executes synchronously with synthetic XML, internal source/destination values and zero delays. `from=2`, `repeat=3` yields two iterations, four CMD/MON responses and two GUI calls; an unknown channel produces no response. CMD destination equals the incoming source; MON uses the internal gateway and retains the internal ID. Reloading a different trigger retains the previous trigger, and the last duplicate replaces the earlier new definition. A prefixed valid numeric range stays within its supplied bounds and `[index]` is replaced. Serialization saves the script reference without Scenario nodes.

A separate subprocess calls the original message substitution with `[1..2]` at the start. It exceeds the one-second bound and is killed. Source inspection separately explains the unchanged zero-position loop. This is bounded observed nontermination, not a measured universal timeout or certification of all malformed inputs.

The complete dispatcher, QThread scheduling, plant/plugin/gateway runtime, nonzero delays, original Qt 4 application and physical Devices do not execute. No script response is elevated into hardware evidence. No original QtTest suite is reported as passing. The earlier inspected virtual-volume test eventually becomes a comment-only method; it is not treated as an executable assertion at that revision.
