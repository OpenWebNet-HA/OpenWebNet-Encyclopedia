## F460: SLEEP request units and completion are separate contracts

The original SLEEP callable manager copies its captured 32-bit field, and the actual invoker reads that field. Zero skips the selected wait request. The nonzero route constructs two 64-bit words, the zero-extended captured value followed by zero, and passes the same object as both request and remaining-duration storage to the imported `nanosleep` call. The packaged candidate C library supplies a matching exported entry and a forwarding wrapper; effective binding and successful operating-system behavior remain premises.

Under the ordinary Linux LP64 `timespec` API contract, that request represents the captured value in seconds and zero nanoseconds. This conditional unit interpretation rests on original call/storage evidence and the API/ABI contract. It does not measure elapsed time or execute a timer. The pinned host headers and primary [Linux nanosleep documentation](https://kernel.googlesource.com/pub/scm/docs/man-pages/man-pages/+/refs/tags/man-pages-6.12/man/man2/nanosleep.2) provide semantic context, not original target headers or proof of an installed binding.

The original retry test is numeric: a return of minus one leads to an error-number check, and only error number four retries. Under ordinary Linux/POSIX semantics that is the interrupted-call path, using the supplied remaining duration. Other error results can leave through the invoker's normal return. The complete operating-system delegate and its error production were not examined or exercised.

The common action caller separately clears its completion byte. On the selected path with operational delay zero and a stored callable manager, it invokes the callable. After a normal return, a fresh test of another operational word decides whether to set completion. Consequently, the selected completion flag can follow a normally returning callback even when that callback left through a non-retry wait-error path. It does not itself certify that the requested wait elapsed. Actual scene configuration, full admission, providers, exceptions, ownership and concurrent execution remain open.

## F461: registered descriptor to actual translator call

The outer selected caller is in the original `coso` executable. A startup request supplies a newly allocated manager to `get_plug_m`; the packaged candidate library has a first-owner/getter contract. Composition with earlier registration remains conditional on the same initialized manager and normal descriptor/list objects being used.

The matcher traverses the manager's field-descriptor and translation-descriptor lists. It compares the selected field against the message, tests the translation descriptor's two direction words, selects the corresponding criterion list, and compares a criterion with the message's numeric field. Only the selected equality path reaches the descriptor's translator callback slot.

For the previously examined automation descriptor, a concrete symbolic source case selects its second criterion list and supplies translator arguments `(2,1)`. The actual call passes the same message, an output-list address and the same descriptor. These are conditional source premises, not injected test objects or naturally received traffic. A local converter also obtains the numeric criterion from a supplied parsed object's decimal string; the original parsed-object producer, full grammar and public WHO interpretation remain open.

The callback's returned value controls further local iteration and cleanup. The inspected code permits further descriptor processing; it does not establish global first-match exclusivity. A zero return is not a physical delivery acknowledgment. The later output callable is an opaque boundary in this packet. A separate clock-comparison gate, active configuration, field registration, provider binding, natural message construction, object lifetime and physical output remain unresolved.

## F460: catalogue opening, SQL producer and selected reader

Fresh original `matrix_mx` source connects a selected reader to the literal `/home/bticino/matrix_mx/MHCatalogue.db` path, an opening request and a 15-column SQL producer. A startup template and constructor-supplied substitutions reach the same SQL member consumed by that reader. The original reader obtains columns13 and14 as text and requests decimal conversion into its own destination fields; the SQL identifies those columns as `EN_KEY_OBJECT.slots` and `AS_OBJECT_SYSTEM.id_system`.

This is positive evidence that selected code consumes catalogue metadata, with its own AArch64 object and pointer dataflow. It does not execute a query, reconstruct every final substituted string or establish full Device/Firmware selection, compatibility, fallback or Prototype/RC policy. Successful filesystem, string and SQLite providers, valid rows and actual conversion outcomes remain conditional. A class/query key is not a physical Device identifier.

## F461: field registration and complete route identity

Original `libplug_scs.so` conditionally registers an actual field descriptor, and the packaged candidate core inserts that same pointer into the manager's field list. This is the list used by the earlier matcher, distinct from its translation-descriptor list. The plugin receives a configuration directory through an original initializer-argument handoff; actual module/config selection and effective provider binding remain premises.

The selected packaged configuration has `SCSEnable=1` and `SCSAIEnable=0`. The original fallback globals start at one for both, so the local registration result depends on whether configuration loading succeeds and which values are used. These safe whitelisted values describe packaged settings, not installed activation, absent capabilities or physical connector roles. The initializer/connect/send/receive implementations remain outside this packet.

The generic local message constructor sets a 64-bit route whose low/high32 words are `(1,0)`. The command-specific wrapper writes the upper word to one, producing `(1,1)`, which matches the selected field descriptor's complete route value. A separate wrapper produces `(1,2)` for another field. Both routes have low word one, so inspecting only that word would merge distinct paths. The matcher separately uses the full route for field matching and its low word for a direction comparison.

Under the earlier same-manager, valid-object/list, due/criterion and provider premises, this constructor result supplies the route and direction needed for the selected translator orientation. Natural command admission, public WHO/dialect interpretation and physical output remain open. The separate SCSAI name/settings do not establish F454-style alarm hardware.
