## Actual event measure → cache change → trigger matcher boundary

WHO17 event callback0xdd9c extracts/atoi-converts DIM, first value and WHERE, then requires original IsMeasureFrame nonzero at0xddd8..0xdde0. For the selected DIM6 or7 path it chooses cache base0x1d0bc or0x1cebc from pools0xde3c/0xde40.

Consequently the selected WHERE1 locations are0x1d0c0 for DIM6 and0x1cec0 for DIM7. They are not command-slot addresses0x1b928/0x1bb28. DIM7's event cache stores a converted integer word, rather than sharing the command branch's normalized byte slot.

The handler compares that cached word with the new atoi value at0xde04. Equality returns immediately. On a difference, **0xde10 stores the new value before the readiness test**. It then loads global0x1b4d4, reads its supplied object's field+4 and returns if that is zero (`0xde14..0xde20`). With nonzero field+4 it loads the separate script-record-list global0x1b4d0, passes the original object's full-frame string at+0x19ec, and tailcalls actual matcher0xc608 (`0xde24..0xde38`).

Thus readiness gates the selected matcher call, not the changed-value cache store. A matching cached value never reaches this readiness test/matcher route in the retained callback. The later matcher sets trigger latches; outer callback invocation and action effects remain the separately reviewed functional2 boundary, not something performed by this handler's direct store.
