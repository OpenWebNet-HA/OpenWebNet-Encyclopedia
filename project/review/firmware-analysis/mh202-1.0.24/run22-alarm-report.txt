## 4. Callback entry closes the conditional pointer join

The stripped callback entry **0x2678..0x26a0** copies its supplied r2 userdata to r8, then executes **ldm r8,{r9,SL}** at0x269c. Under the explicit premise that this userdata is the same private object initialized above:

- r9=private[0]=manager+32;
- SL=private[1]=the corresponding declared descriptor;
- [r9+4]=manager+36=field_receive;
- [r8+4]=SL, so the descriptor reference passed to the run21 callback and its SL+56 gate share the same back-pointer under this premise.

This is a complete static pointer composition **from initialization to callback-entry state**, not proof that any outer transport/source registration actually passes that userdata or invokes the callback. Recovering that real activation would cross the deliberately excluded connection/source internals; it stays a boundary rather than being silently filled with a model.

The two finite host ledgers compose the declared ordinary descriptor and SCSAI descriptor separately. Both derive the same field callback candidate; they differ in SL+56 and therefore in run21's already established criterion4 gate. No body classification, real field record, parser, function-pointer invocation or publication runs in these host ledgers.
