While started sl remains0, `0x9570..0x9580` compares the first six bytes of the just-read remainder against exact original literal **` BEGIN`** (one leading ASCII space). Equality:

Other pre-BEGIN records continue through separate directive checks; they do not take these head stores or the later started append branch. This is a prefix rule: it does not require that the marker end immediately after BEGIN. ## Construction EOF and execution END are different boundaries

Construction has no END stop on the started path: after creating its node, it jumps directly back to fscanf. `0x980c` checks fscanf return against−1; on equality `0x9814` adds2 to that return value and returns **1**, independently of started. Thus reaching this EOF return without a matched BEGIN does not produce the selected head payload stores, yet still returns nonzero locally. This is an exact limited counterexample to equating this return with “a valid initialized list was proved”; it is not an observed outcome of feeding an invalid script, an assertion about unknown allocation bytes, or a full error-policy verdict.

The execution tail separately compares current line text's first three bytes with exact public literal **END** at `0xaa68..0xaa80`. Equality requests the end helper repeatedly until its nonzero return (`0xaa84..0xaa8c`); the ordinary next-node path is bypassed. Nonmatching text instead loads esegui+8, stores the successor into esegui and returns to `0x9b2c` (`0xaa94..0xaaa0`). The selected construction code can append records that follow an END record; their presence is distinct from whether ordinary execution ever reaches them.

At `0x9b34..0x9b50`, actual execution reads node+4, requests fseek with whence0, then fgets into the1024-byte line buffer. It does not use node0 as an implicit file-line index. None of these imported effects is executed here.

## What this adds to GOTO

Run17 proved GOTO's two pointer positions: matching head leaves esegui=head; a later matching successor leaves esegui at its predecessor; the subsequent normal interpreter tail advances once. Those remain source facts, not new experiments in this batch.

This construction source now supplies a concrete head identity: **the matched BEGIN record**. Under consistent shared-global bindings, valid reachable nodes, ordinary helper return and reaching the non-END outer continuation, GOTO to that head label advances to the first appended source record. This is not evidence that GOTO necessarily skips an ordinary first action: the previous `[10,20,30]` examples were deliberately arbitrary synthetic labels, while this pass establishes how a BEGIN entry can occupy the head in the actual program.

The helper's search of successor labels, handling of missing or duplicate labels, head-marker pacing and numeric bounds do not become a complete language/termination proof. This batch neither runs GOTO nor repeats its prior pointer/counter matrix. Command-gate clearing, R/P production, Only-if semantics and live process/lifetime behavior are untouched.
