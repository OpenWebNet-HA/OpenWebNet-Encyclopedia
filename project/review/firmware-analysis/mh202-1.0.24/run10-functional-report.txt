**Static, conditional join; original execution **0**.** This batch closes the selected numeric record identity and read/write correspondence between the previously reviewed calendar-result stores and `IIF`. ## Material findings

The numeric assignment and selected numeric `IIF` branch use an 8-byte-stride table with names beginning at record+0 and signed integer values at record+4. They call the same named lookup provider, which is **lookup-or-create**: on a matching name it returns the existing index; on the first empty name it requests a name copy, initializes value+4 to 0 and returns that index. Thus selected missing-name handling is not simply a failed read.

There is a concrete text-identity qualification. The executable's assignment parses a decimal ID after `$V`, then formats the key with `%.3d`. The selected library `IIF` branch removes `$V` and looks up the remaining operand text directly. For ordinary supplied ID1, the assignment key is `001`; an IIF operand supplied as `$V001` can address that same key under the shared-global/provider premises, while text `$V1` queries a distinct name `1`. No claim establishes which spelling a missing configured generator actually emits or how the full operand parser transforms it.

Stored values 0/1/2/−1 from the earlier reviewed calendar/time branches are not themselves Booleans. They are read as signed integers by the selected IIF branch and passed with an explicit operator/right operand to `INT_OPERATORI`. Its byte result controls how many comma-prefix removals IIF requests on the current global line. The caller then tests that changed line against later action prefixes, including `OWRITE`; it does not branch on the IIF return value.
