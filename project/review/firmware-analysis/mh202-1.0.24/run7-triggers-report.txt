## Isolation and execution boundary

Every case creates a fresh ARM emulator and independent mapped memory. Code page permissions are read/execute after writing the selected function. Strings and stack occupy separate read/write maps. No target filesystem, device, network, process, dynamic-loader or syscall implementation is supplied.

The harness permits original program counters only inside the selected function; it rejects unknown code addresses, any interrupt and invalid/unmapped memory. It never automatically maps a fault. Each call has a100000-instruction cap and1-second emulator timeout, and must return normally to the private sentinel at0xf000 without a guard violation.

Two imported PLT sites are explicit host primitives: strlen at0x9b5c and atoi at0x994c. They read bounded emulator strings, compute declared host results, update emulated registers and return to emulated LR. They perform no target or host I/O. Numeric fixtures are nonoverflow decimal strings; this does not implement packaged libc malformed-input behavior. Original BL/call-site and comparison/branch instructions run, while the two primitive bodies do not. Primitive75 is separate from1485 original visits; counting both as original instructions would be incorrect.

The harness's initial author version had a Python syntax error before import or instruction execution. It was corrected without changing inputs, caps or isolation; no failed original experiment is hidden or promoted as a result.
