## Original grammar and real ASCII table data

The ordinary parser uses direct character/token instructions, not an unknown regex engine or registry. It calls normal prefix/suffix string helpers, checks the actual delimiters and scans original input characters. Its numeric-character test at `0x278c..0x27b0` follows two original data-pointer indirections and tests mask`0x0008` (bit3) of a GLib halfword entry. The host does not replace that classifier or field extraction.

Original source/relocations identify:

* libopenmsg GOT `0xee78`: R_ARM_GLOB_DAT `g_ascii_table`;
* candidate GLib exported pointer cell `0xe50c8`, whose original word points to table `0x9ed8a`;
* that cell's original R_ARM_RELATIVE relocation;
* the original512-byte character table, read from the packaged GLib ELF.

The harness maps the original GLib data at private base `0x10000000`, resolves the libopenmsg GOT to the relocated exported cell, and adds that private base to the cell's original table pointer. These are **two explicit setup data relocations per private session**, not executed loader code, callbacks or firmware instructions. There are two private sessions/four setup writes total. The serializer reuses the query's session and adds no setup relocation. Original GLib mappings are read-only/nonexecuting, and a native-read guard permits only that4-byte exported cell and512-byte table. Each parser makes four recorded original GLib data reads: the cell and the three selected digit entries. No original GLib code executes.

Original `buf_to_openmsg` invokes real `new_open_msg` through its redirected PLT at `0x27d8`. The ordinary command branch stores kind1 at `0x2834/0x2838`, then executes its own WHO/WHAT/WHERE token/field paths. The query branch invokes original WHO helper `0x23b0` and WHERE helper `0x2488`; it extracts DIM into object+32 and, with the original value list still null, stores kind3 at `0x2a90/0x2a98`. Exact original helpers, classification, allocation wrapper and pointer stores execute; only ordinary string/allocation operations are modeled.

## Native query serializer uses the actual parsed object

The third entry is deliberately separate in the result ledger: top-level index2 consumes the object produced by parser entry1 in private session1. It does not reconstruct a postparsed fixture. The48 object bytes are checked unchanged after serialization.

Original serializer `0x1e9c` reads the actual null parameter/selector lists, WHO/WHERE/DIM pointers and kind3. It duplicates the ordinary WHO/WHERE strings, obtains the DIM copy using actual original format `%s`, then its kind jump table `0x1fb0..0x1fcc` selects `0x202c`. Original format `*#%s*%s*%s##` is passed with those actual pointers to the finite printf primitive model at `0x2040`; `0x2048` stores its allocated output pointer. Normal cleanup precedes the original explicit return0 at `0x2020`.

The cleanup-only `free_gchar` model is separately audited against its candidate original libutils wrapper `0x1904..0x192c`: for a valid pointer slot containing a nonnull allocation, free it and clear that slot; a null pointed value returns without a store. It maintains a private allocation/free ledger rather than invoking an OS allocator. The model's r0 is ignored by this selected original continuation, which finally sets return0 itself. This wrapper is not misrepresented as native execution or central parser/serializer grammar.

This narrows thermo15's serializer-return0 premise for exactly this native-produced WHO4/WHERE1/DIM0/kind3 object. It does not execute thermo plugin entry/configuration, scsDest, its output records or any STM/transport. Likewise COSO15 now has an original parser/kind result for its selected `*2*0*0##` text under these conditions, but the whole nonnull record replacement, synchronizer registry, callback/queue identity and natural correlation remain separate.

## Containment and primitive scope

The harness is fresh MH202 code/layout work; it reuses only the RECORD-verified independent Unicorn2.1.4 analysis package. Its historical tool-storage location under the F454 tooling directory supplies no F454 firmware, layout or harness.

Original libopenmsg image bytes are read/execute-only; original GLib mappings are read-only/nonexecuting. Private stack/input/output slots/heap are the only writable regions. Native PCs are allowlisted to the actual normal parser, allocator wrapper, selected field helpers and serializer. Unknown calls, interrupts and invalid/protected accesses abort; each top-level entry has100,000-hook and100,000-emulator-instruction caps. C-string reads are bounded4,096 bytes; modeled allocations fit a64KiB private heap and each allocation is at most4,096 bytes. Output slots are initially null for parser entries, so existing-object free/replacement branches are not pretended to execute.

Ordinary primitive models are strlen, prefix/suffix checks, comparison-sign g_strcmp0, strchr, bounded g_strndup, g_strstr_len with selected length−1, successful g_malloc0(48), g_strdup, two exact source-verified printf formats, and the cleanup-only free_gchar contract above. They do not implement a replacement grammar, numeric field classification, registry, regex or invented object state. Lists remain null in these cases; unexpected list/other imports abort. No original libc/GLib, configured plugin initialization, allocation failure/error/NULL-input/Unicode/replacement cases or full accepted-language domain is tested. No target OS/process/syscall/network/device or authentication/handshake/caller-framing branch is executed.
