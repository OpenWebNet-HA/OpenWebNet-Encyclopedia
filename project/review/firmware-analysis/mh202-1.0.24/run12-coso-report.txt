# MH2021.0.24 run12 — actual lighting STM request, pending ID and timeout policy

## Result and limits

The lighting **STM** has concrete original callbacks and44-byte private context governing requests, field callbacks and timer completion. A supplied parsed ordinary kind1/WHAT1 request, starting in numeric state0, is appended to the field-output list, stores its record ID/address/kind, changes state to1 and requests a timeout source with argument1000. A selected field callback with matching stored ID and numeric status word1 changes state to2; for this ordinary request kind, the following branch resets state/timer, queues an OPEN ACK and appends the field record. Matching status2 queues NACK/reset instead. Timeout in state1 queues NACK; timeout in2 or3 queues ACK, then invokes a supplied completion callback and resets.

This is source control/data flow and six finite host decision/effect transcriptions, **not** executed original callbacks, actual plugin loading/timer scheduling, accepted full commands, transport delivery or physical completion. Numeric state/status namespaces remain local. Original ARM/vendor/parser/JS/PHP execution, original instructions executed, emulator hooks and live I/O are all **0**. All originals, earlier research and repository files remain read-only; no auth/HTTP/template route or credential material is inspected/exported.

This selected busy path resets the pending context; it does not establish the destination request’s full ID/transport semantics or actual receipt delivery.

For state0 it uses input record+0 as the supplied parsed object, sets record+4/+8 to1, and dispatches parsed kind+44. Selected kind1 reads WHAT text+8 at0x1c64 and decimal-converts it. WHAT1 follows signed lower/range guards0x1c74..0x1d10 to **0x1c50**; no parameter-list branch is needed for this command. Broader WHAT domains and kinds are not inventoried here.

## 3. Selected field callback, ID/status branch and ordinary completion

Field callback obtains context from descriptor+56. Input record+56=3 uses its parsed pointer directly; value2 requests buf_to_openmsg and replaces prior text/representation before continuation. Only the direct parsed premise is used in the host cases. That is a different boundary from proving a complete raw status parse.

For state1, **0x1a34..0x1a40** compares context+8 against input record+60. In the selected **matching-ID** path, record+52=1 writes state2 at0x1a4c/0x1a50. Numeric2 instead calls reset and queue_nack_to_open at0x1a60..0x1a70 and returns0. These numbers are actual local branch values; this report does not assign a global transport/ACK enum based solely on them.

After the state2 store, **0x183c..0x1850** examines saved parsed request kind. Kinds2 or3 take a different state3/address/query policy. Selected saved kind1 instead goes straight to **0x1a04..0x1a30**: reset context, queue_ack_to_open on the supplied output list, set incoming record+8 to3, append that record to the output list and return0. This branch does not require the later query address parser or value/dimension comparison. It is a local receipt/list policy, not a physical lighting-readback proof.

The matching-ID comparison is **not a demonstrated universal guard over all completion routes**. The source’s ID-mismatch branch at0x1a40 also reaches0x183c, and an ordinary saved kind1 can therefore reach that ordinary completion branch if an otherwise eligible field callback is supplied. Outer routing/key/ownership constraints have not been traced far enough to assign a real cross-request outcome. The report neither claims completion requires ID equality globally nor promotes this local path to a defect. Precise outer callback admission is a distinct remaining question.

Separate query-kind/address/value work at0x187c onward and state3 behavior are not expanded into another address matrix. Earlier TR WHAT/body and reverse-address findings are inputs for future joins, not silently treated as STM state execution.

## 4. Timeout, reset and concrete receipt construction

Timeout callback **0x1678..0x16f4** starts two local list pointers at0. State1 requests queue_nack_to_open; states2 or3 request queue_ack_to_open; state0 or other displayed states go to reset without that selected queue/completion path. After a queued receipt it loads descriptor+60 through context+0, passes local-list addresses and that manager pointer to the **supplied context+40 completion callback**, then resets and returns0. Callback implementation/publication and callback-after-destroy scheduling are not reconstructed.

Reset **0x15f8..0x1678** writes state0, saved ID−1, saved dimension−1 and saved kind0; frees/nonzero-clears copied strings+20/+24/+28; requests g_source_destroy for a nonnull timer pointer then clears+32. Descriptor/context/completion fields+0/+36/+40 remain outside those reset stores. No actual memory/source lifetime guarantee or cancellation race behavior is inferred from static calls.

Same-build core queue helpers **0x2a44..0x2b5c** resolve the receipt boundary concretely. queue_nack_to_open duplicates exact literal **`*#*0##`** and assigns type+40=7; queue_ack_to_open duplicates **`*#*1##`** and assigns type+40=6. Both allocate a64-byte zeroed message, request a timestamp, finish metadata+4=2/+8=4/representation+56=2 and append to the supplied list. The intermediate stores differ from these final fields; these numeric types are distinct from STM state numbers and parsed kinds. No original allocation/time/list/format primitive executes in this static batch, and no output transmission is shown.
