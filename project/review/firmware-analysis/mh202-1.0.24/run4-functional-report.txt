## Two original OWRITE callers

Original bt_script compares current line text with the **seven-byte `=OWRITE` literal** at `0x9f84..0x9f94` (pool `0xa9d0`→literal `0xaf8c`). After a selected string lookup, `0x9fe0..0x9ff8` computes the argument from a string-variable record and the destination from the numeric-record array plus a precomputed offset. Call `0x9ffc` invokes imported OWRITE. The very next instruction `0xa000` branches to **`0xa480: str r0,[r4,#4]`**, then continues at `0xa4f4`. See [owrite-assignment-caller.txt](owrite-assignment-caller.txt) and [return-store-and-standalone-caller.txt](return-store-and-standalone-caller.txt).

This is a direct source def-use join: the helper's returned integer becomes the selected numeric record+4 value. There is no intervening conversion to an action-success Boolean. The destination setup uses the numeric-array pointer at executable base+0x418 (its exported Valori_num), but the full assignment parser, variable-index validation and configured statement syntax remain unproven. The prefix literal alone is not a full valid DSL example.

The same body separately compares current line text with the **six-byte `OWRITE` literal** at `0xa4f8..0xa50c` (pool `0xa9fc`→literal `0xaf8d`). Selected string lookup supplies the argument, then call `0xa580` invokes OWRITE. At `0xa584` the code begins preparations for later prefix comparisons and overwrites r0 with the current-line pointer at `0xa58c`; it does not inspect or store the OWRITE result first. This selected standalone caller **ignores the returned value**. Other command paths and later script behavior are separate questions.

Run3's marker branch returns1 before F emission. Joined to the first caller under the stated function/provider assumptions, that1 is stored in a numeric value slot. Joined to the second, it is unused. A source return1 therefore cannot be renamed “the command was sent,” “action succeeded,” or “scenario ran.” The three finite source-return examples in [host-local-models.json](host-local-models.json) merely show storage/ignore behavior; no original helper or numeric-variable update executed.

## Bounded SLEEP parameter/delegate path

Original `libdomotica!SLEEP(unsigned long,char*)` at `0x3ab4` first compares the entire unit string to exact literal **`ms`** (`0x3afc..0x3b1c`, pool `0x3e04`→`0x94e0`). That branch at `0x3d48` eventually passes **amount×1000** to imported usleep at `0x3dc8`. This is a microsecond argument under the ordinary usleep contract; no actual elapsed time was measured.

For other strings, the first character selects unit conversion: `m` takes arithmetic amount×60 (`0x3b54..0x3b68`), `h` takes amount×3600 (`0x3b70..0x3b8c`), while `s` and the displayed fallthrough retain the amount (`0x3b20..0x3b90`). These are source guards, not a declaration that arbitrary strings are valid script syntax. Counter updates occur separately; no new physical interpretation is assigned to those globals.

The selected non-ms amount is compared unsigned against **300** (`0x3bd8..0x3bec`). Values at most300 reach one `my_sleep_select` call. Larger values compute quotient/remainder by300, invoke `my_sleep_select(300)` for each whole chunk and invoke it for a nonzero remainder (`0x3c28..0x3d40`). See [sleep-unit-selection.txt](sleep-unit-selection.txt) and [sleep-chunk-and-ms-delegates.txt](sleep-chunk-and-ms-delegates.txt).

Candidate libcommon exports `my_sleep_select` at `0xfa50`; libdomotica directly needs `libcommon.so.0`. In that original helper, argument r0 is stored as timeval's first word and its second word is initialized0 (`0xfa5c/0xfa60`), then it calls select with no descriptors and that timeout (`0xfa68..0xfa88`). It loops according to the remaining first word and handles the displayed EINTR branch. See [candidate-seconds-select.txt](candidate-seconds-select.txt). Under ordinary timeval/select contracts this is a **seconds** delegate; actual interruption, provider binding, overflow, scheduling and wall time are untested.

Six finite nonoverflow host examples transcribe only the selected arithmetic/call plan: amount2 with s/m/h gives2/120/7200 seconds before chunking; amount2 with exact ms requests usleep2000; 300s requests one300 chunk; 301s requests300 then1. These are not executed original unit parsing or sleep tests. No configured `.spt` statement was supplied and the complete interpreter unit-string extraction grammar remains open. SLEEPRANDOM, dates/time matching and R/P IPC producer discovery are not silently included in this bounded result.
