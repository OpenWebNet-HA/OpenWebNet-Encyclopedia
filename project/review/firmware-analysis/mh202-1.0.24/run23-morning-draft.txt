## What this adds to the encyclopedia

The principal gain is a build-specific account of how MH202 scenario management, its interpreter and its COSO translation framework fit together. It separates command vocabulary from implementation state, distinguishes several incompatible parser/object layouts, and supplies evidence for selected functional paths without treating generated examples as hardware captures. The encyclopedia now has a main firmware profile and focused state/routing, record/script-lifecycle and functional-translation continuations, with source excerpts, reproducible collectors and independent reviews in the review capsule.

The evidence supports narrower and more useful statements than a generic feature list. WHO17 is owned by the task manager, while COSO's WHO0 scenario translation is a different subsystem. Numeric script filenames and PHP index entries follow different gap rules. A stop-request state is not proof that a child is running. Manager variable slots are not automatically interpreter variables. An ordinary software receipt is not proof of a bus acknowledgement or measured temperature. These distinctions are retained alongside the existing published command vocabulary. See the [main encyclopedia profile](../../../../OpenWebNet-Encyclopedia/reverse-engineering/firmware-analysis/mh202-1.0.24.md) and the [frozen scoped findings through21](reconciliation/run22/SCOPED_FINDINGS.md).

The examined archive is `MH202_010024.fwz`, SHA256 `bb561eb2b6b476de21cc4981234108b0698c2a58b1e229f2909ef4e49aef9df7`. It supplies normal/recovery root images, a kernel and an update manifest. The manifest references `2.xtz` and `4.xtz`, which are absent. Actual configured scripts, mounted extra data and language-resource contents therefore remain unknown. Script/index consumers establish what uses extra4; they do not reconstruct its contents. Normal/recovery file comparison and selected MH202-versus-F454 file/text hashes were verified; matching names did not authorize importing F454 layouts or results. [Inventory](inventory/REPORT.md), [initial platform findings](boot/run1/REPORT.md).

Most conclusions are static code or source observations. Fourteen canonical memory-only original-code corpora add68 top-level entries, including two prefixes stopped before a selector read. They record31581 original instruction visits,3140 declared primitive callbacks,128 redirects to original definitions,24 private return boundaries and2 selector-read stops, totaling34875 code-hook visits. Setup writes and verification replays are not accumulated. The count is an execution ledger, not a percentage of firmware coverage or a measure of independent test quality. Ordinary string/allocation/list/clock/import models and fixture state remain explicit in each corpus. No firmware process, target OS call, PHP/JavaScript, service, gateway or bus operation has run. [Execution state](RESEARCH_STATE.json), [checkpoint22 verification](validation/run22/final-checkpoint.json).

The C++ parsers differ: MH202 libopen uses90-byte address slots and libcommon uses130-byte slots. COSO's libopenmsg parser instead has48-byte pointer/string objects, and its envelope records are64bytes. Their kind values and offsets belong to their own implementations. Descriptor criteria, reverse routing, WHO values, envelope metadata and parsed kinds must also be kept separate. [Initial parser split](protocol/run1/REPORT.md), [actual COSO parser objects](protocol/run16/REPORT.md), [command-side selector copy](protocol/run20/REPORT.md).

## Scheduler, script lifecycle and variables

The task manager's post-parser WHO17 dispatcher selects launch, stop, enable and disable operations for WHAT1..4. Original status-renderer code keeps availability and execution/control state separate. The loader checks numeric script paths1..300 and continues across failed opens; selected PHP index code stops at the first empty scenario name and sends the separate XML id as WHERE. Neither enumeration proves a universal physical scene-address range. [Task manager](functional/run1/REPORT.md), [web consumer](web/run1/REPORT.md).

Selected event matching can latch a trigger and invoke its stored callback. A configured panic-frame comparison and a working-mode4 path set a shared command gate. Query readiness is a separate object field and cursor. RESTART is established in restoration of saved-active records before an independent always-start pass; it is not proven as universal EOF rerun. FIFO records establish conditional PID/control transitions and selected producer correspondence, not successful delivery or child liveness. Full gate clearing, some R/P producers and the configured lifecycle remain open. [Control/restoration](functional/run2/REPORT.md), [FIFO/lifecycle](functional/run3/REPORT.md), [readiness/gate](lifecycle/run6/REPORT.md).

The interpreter has actual IIF/comparison, calendar/time, sleep and GOTO paths. Its numeric records use string names; formatting an assignment key as001 does not make it the same lookup key as1. Selected IIF paths consume stored values and request later action copying, but full configured source-to-action behavior is not executed. CHKTIME uses localtime, while selected CHKDATE uses gmtime; this is a source/API distinction, not an observed clock discrepancy. Mixed logical separators share state in the selected scanner; finite ledgers do not define the complete grammar or product precedence. [Numeric/IIF join](functional/run10/REPORT.md), [calendar](functional/run9/REPORT.md), [mixed logical state](functional/run13/REPORT.md).

The concrete source-list head is the first matching BEGIN entry. GOTO's head/predecessor policy must be read with the caller's subsequent advance; it does not by itself show a skipped first action. Construction EOF and execution END are separate. A selected OWRITE marker check suppresses its request, and its integer return is not transport success; it does not establish universal suppression of every action. [BEGIN/head](lifecycle/run18/REPORT.md), [GOTO/caller](lifecycle/run17/REPORT.md), [action guard](functional/run3/REPORT.md), [return use](functional/run4/REPORT.md).

WHO17 DIM6/7/8 use distinct direct storage: integer words, Boolean bytes and guarded adjustment. DIM6 stores before its response-range check, DIM7 checks before storing, and DIM8 emits adjusted DIM6. Their local2/3 results are not established wire ACK/KO. Separate event caches store changed values before readiness gates matching. Neither domain is automatically the interpreter's named heap records; no natural command-event-script bridge has been demonstrated. [Direct slots](functional/run19/REPORT.md), [event/cache separation](lifecycle/run19/REPORT.md).

Fresh original parser-to-same-object serializer sessions return both exact strings. Original GLib foreach and the original parameter callback run for the sound case; ordinary string/reallocation/free helpers remain models.
