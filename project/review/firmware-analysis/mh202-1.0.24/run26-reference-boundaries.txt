# WHO14 and WHO15 reference boundaries for MH202

This is a bounded reading of two existing curated reference pages, with exact pre-edit hashes/snapshots and twelve line/excerpt locators. It adds no original firmware execution, new public-source/database/specification review, oracle run or physical observation. The repository's reviewed/run25/WHO14_WHO15_REFERENCE_PIN_SUPPLEMENT.json is separate from, and does not change, the fourteen-page checkpoint25 snapshot index.

The current WHO14 page attributes WHAT0 Lock actuator and WHAT1 Unlock actuator to a specific MyHOME_Suite ScenarioDevices capability. It explicitly lacks a dedicated public WHO14 PDF in the current corpus and does not define a universal new address domain. Those attributed labels should remain scoped to that actuator Object/system. A firmware-local body/opcode or postparsed WHAT<=1 guard does not by itself prove physical locking, add undocumented WHAT values or validate every target. WHO14 being usable as a scenario action does not make it WHO0 or WHO17 scenario management.

The current WHO15 page keeps button00..31, WHAT phase parameters and source WHERE separate. Published leading-zero examples are retained; WHAT#1/#2/#3 and WHERE#3/#4#I4 belong to different fields. A selected compiled formatter can corroborate its own zero-padding request and parameter decomposition without proving the published full grammar, physical interaction timing or universal source address acceptance. Local signed/unsigned conversion guards require their own upstream admission premises; they are not a new arbitrary-input defect or support table.

CEN's physical/button vocabulary and its relation to CEN+ remain as already curated. A new MH202 source path must not transfer CEN+ virtual-Object rules into WHO15, assign scenario-management meaning to button numbers, replace published press/hold timing with a local receipt path or turn a software ACK/NACK helper call into proof of SCS transmission. Numeric descriptor criteria, direction, parsed kind, envelope fields and private state remain different representations.

The new implementation notes should therefore link the exact MH202 source/report/review boundaries and retain the existing labels/forms. Original static byte construction, separately supplied reverse examples, finite host ledgers, actual isolated helper execution, historical client/database implementation and physical observation are different methods. This reference reconciliation neither reaudits the original external sources nor closes full-source or Device review gates.
