## Material result

The actual `bt_script` `=CHKTIME` branch calls `CHKTIME(char*,char*)` and stores the returned number in the selected numeric record. In the packaged `libdomotica` implementation, exact first argument `SYSTIME` selects current local hour/minute comparison against two fixed-position fields of the second string. The source returns **0 for equal hour/minute, 1 when current hour/minute is later, 2 when earlier**, and **−1 for another first argument**. This is a three-way numeric comparison, not a Boolean condition or a duration timer.

The original argument-extraction calls include overlapping `strcpy` source/destination ranges. Static call arguments and a deliberately hypothetical forward-copy model are recorded separately; neither proves the actual libc result or that the supplied current-line candidate is a valid complete DSL statement. The missing configured extra/4 assets remain important to that gap.

## Actual source branch and call arguments

`chktime-prefix-and-extraction.txt` covers `bt_script` VA `0x9da0..0x9e58` (exclusive end). At `0x9da4..0x9db4`, it compares the first **8** current-line bytes against literal `=CHKTIME` (`0xaeff`, pointer word `0xa9b4`) and proceeds only for zero `strncmp` result. This is a prefix check; it does not itself validate a closing delimiter or complete statement.

The selected path then performs these actual operations:

1. Clears 10 bytes at `sp+53` (`0x9dcc..0x9dd8`). Finds the first `(` in the current global line and requests `strcpy(line, found+1)` (`0x9ddc..0x9df0`). Source and destination can overlap; no null-result branch appears between this search and copy.
2. Requests `strncpy(first_buffer,line,10)` (`0x9df4..0x9e00`), then `strtok(first_buffer,",")` (`0x9e04..0x9e0c`). Its returned pointer is unused; the buffer itself is later passed as argument 0. In the bounded model, the comma lies within these ten bytes and terminates the selector.
3. Finds the first `"` in the changed line and requests `strcpy(line,found+1)` (`0x9e10..0x9e24`), another potentially overlapping copy. Calls `strtok(line,"\"")` and requests `strcpy(line,returned_pointer)` (`0x9e28..0x9e3c`).
4. Passes the first buffer in `r0` and the changed global line in `r1` at `0x9e44..0x9e50`. This calls the executable's imported `_Z7CHKTIMEPcS_` PLT entry `0x91f4`; the selected library defines that exact symbol at `0x1d60`, size 792. This is an observed declaration/call/provider match, not a full runtime dependency/binding proof.
5. `0x9e40..0x9e4c` forms the selected numeric-record pointer from `Valori_num` and `r9`. After the helper, `0x9e54` branches to `0xa480`, which stores **r0 at record+4**, then continues at `0xa4f4`. `numeric-return-store.txt` saves the store. The caller does not reinterpret the returned code as Boolean in this selected path.

`conditional-extraction-model.json` uses the current RHS-line candidate `=CHKTIME(SYSTIME,"0000000012:34")`. This model runs no `strcpy`, original interpreter or packaged script; outer numeric-variable parsing, actual copy behavior and deployed source syntax remain open.

## Complete selected helper and exact comparison

`chktime-complete-body.txt` saves the entire `CHKTIME` body and literal pool (`0x1d60..0x2078`). PIC arithmetic at `0x1d78` plus the original word at `0x2054` gives base `0x12114`; pointer `0x2058` resolves to exact literal `SYSTIME` at `0x91b8`. `strcmp` at `0x1d9c` branches on nonzero at `0x1da8` to the parameter-error path, returning −1 (`0x203c..0x2050`).

For exact `SYSTIME`, `0x1de0` calls imported `time` with a stack pointer; `0x1dec` passes that pointer to imported `localtime`. The helper then uses the returned structure pointer without an intervening success/null check. Its fields at offsets **8 and 4** correspond to `tm_hour` and `tm_min` under the ordinary selected 32-bit libc ABI; no libc or environment executes here.
