# MH202 run13 — original special-DIM1 parser writes before selector read

Two bounded native-entry experiments close a specific boundary left by `triggers/run10`: for the selected short WHO13 measurement inputs, both original common130 constructors and complete normal parser paths execute, but neither their writes nor the surrounding selected taskmanager instructions write the six-word selector region. Execution stops **before** original taskmanager instruction `0xca48` can read its first selector word. No selector value, comparison outcome, comparator return, hit, defect or physical behavior is inferred.

This is selected native code with explicit same-build common providers and ordinary C primitive models, not a complete deployed caller join. A fresh static upstream check distinguishes the entry-only first fixture from a second fixture whose received text satisfies the actual outer special-selector prefix. The outer matcher itself is not executed.

## Actual caller and experiment inputs

Original taskmanager matcher `0xc608` saves incoming event text in r7. Its `strncmp` at `0xc620` compares8 bytes against literal `*#13**22` at `0x1099a`. Equal selects function pointer `0xc8e0` from pool `0xc690`; unequal selects ordinary comparator `0xc6dc` from `0xc694`. At indirect call `0xc658`, r0 is the trigger-record text pointer loaded from `[r4]`, r1 the saved incoming text. This is an indirect selected route, not a direct BL to the special entry. No complete indirect-caller inventory or absence claim is made.

Special entry `0xc8e0` separately checks the first4 trigger bytes against `*#13` (literal `0x109a3`, comparison call `0xc91c`). The first parsed trigger DIM, not the parsed received DIM, selects the local DIM1 branch. These are distinct selector conditions.

## Frame ownership and executed path

Offsets are relative to the special helper's local SP after its16-byte register push and15,376-byte allocation (`0xc8e4/0xc8e8`). The two original object bases are SP+0 and SP+7,676; the selector region is `[SP+15,352, SP+15,376)`. Saved entry registers begin at SP+15,376 and are a separate region.

Native taskmanager constructor calls `0xc900/0xc90c` invoke actual common C1 `0x24bf0`, which invokes original reset `0x24aa0`. Parser calls `0xc940/0xc960` invoke original common `CreateMsgOpen` `0x2646c`, with actual source strings/lengths and object pointers; snapshots are taken after normal returns at `0xc944/0xc964`. Each parser resets its own object again, copies the raw text, updates its original length fields and invokes original `IsCorrect` `0x25e38`. The actual measurement-field helper `0x25b00` and WHO/WHERE suffix helpers `0x25010/0x252bc` execute. This is the common130 layout, not the libopen90 layout.

Native DIM accessor `0x24948` is called at `0xc96c`, and the normal integer conversion yields1. Original comparison `0xc974` and equal branch `0xc978→0xcac4` set byte cursor r5=0 and branch to `0xca40`. Original `0xca40/0xca44` compute r3=localSP+15,352. At that point the harness stops at the code hook for `0xca48` (`ldr r4,[r3,r5]`) **without executing it**. No value accessor indexed by that word, string comparison, destructor/return tail or hit consumer executes.

Every original data write is guarded/recorded via the CPU memory-write hook; every modeled primitive write is independently guarded/recorded at the explicit write helper. Original and modeled primitive reads into the selector test region are forbidden before the stop, and none occurs. Code-hook accounting is distinct from these memory-observation callbacks.

Across the two selected traces,882 write events are recorded:252 original-instruction write events and630 modeled primitive write events. None overlaps the selector region. Object-intersecting writes reach at most SP+15,352 exclusive, exactly its lower boundary. Writes into callee stack frames or the saved-entry-register region are retained as separate events, rather than mistaken for object writes. Full trace/event arrays and addresses are saved in `preselector-results.json`; the host collector recomputes interval overlaps, counts and the original VA/file mapping.

The24 selector bytes are deliberately distinct private canary bytes `80 81 … 97` before entry and remain identical at the stop. They are **test state supplied by the host**, not claimed original initialization or an observed production stack value. They are never consumed by a selector read. This demonstrates selected nonwriting, not a match-all result or evidence of a particular production word.

## What is newly established and what remains open

Run10's selected default-reset interval analysis excluded complete parser effects. This batch executes those effects for these two short native accepted measurement pairs and shows the selector region remains untouched through the original DIM1 branch's first read boundary. The original local DIM0/22 selector-store matrices are not rerun as new coverage. Ordinary run11/12 normalization cases are also not rerun.

This does not prove a global bound on all parser writes: raw/field copies and value-slot progression have input-dependent lengths/counts. No malformed or excessive-length/count inputs are explored. Live provider overrides, stack reuse/history, configured trigger contents, other paths and actual incoming event provenance remain unknown. No supplied canary is used as an original selector initialization. A production selector value/outcome cannot be obtained by replacing unknown stack state with zero, an arbitrary value index or a sentinel. The comparator stops before that unresolved dependency.

The package's ordinary taskmanager direct NEEDED order places common before open, as established in read-only run11/10 metadata. Here the same-build common definitions are explicitly selected by native redirects. No live loader/interposition/global environment or full taskmanager closure is executed or newly claimed.

## Containment and accounting

The fresh MH202 harness extends the verified same-build run11 setup in new files. Taskmanager is mapped read/execute at its original VAs, common read/execute at private base `0x10000000`; only private stack/input/heap are writable. Unknown PCs, interrupts and invalid/protected accesses abort. Read/write guards reject selector consumption before the explicit stop. Native entry is `0xc8e0`; execution never continues into an arbitrary selector index. There is a100,000-hook and100,000-emulator-instruction cap per top-level call.

Primitive models cover only ordinary `memset`, `strcpy`, `strlen`, comparison-sign `strcmp`, four-byte `strncmp`, `strchr`, `strtok`, exact selected `strncpy`, `strcat` and decimal `atoi`. C-string reads are capped4,096 bytes; token scans are region-bounded with per-byte checks. Native parser/predicate/constructor/getter code is not replaced. No real libc/allocator, target OS/process, loader, syscall, network/device, interpreter or authentication route executes. The analysis-tool package alone is RECORD-verified; no F454 firmware/layout/harness is imported.
