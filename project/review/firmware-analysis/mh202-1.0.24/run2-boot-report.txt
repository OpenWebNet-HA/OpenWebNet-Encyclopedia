# MH202 run2: actual environment selector, configuration and child launch filter

The inspected daemon selects its running-firmware-copy flag from **`MYRECOVERY` in the process environment**, not from a demonstrated `/home/bticino/sp/Recovery` file consumer. Exact value`yes` selects copy2; other values select copy1. Copy2 enters a concrete minimal route which stores working status2 and invokes the child launcher.

A second substantive distinction is now supported by original code: **a child’s packaged `working_mode=0` is not simply “disabled.”** In selected launcher0x14dd0, it is skipped only when the current working status is2. For other current statuses that filter does not exclude zero-mode entries. On this path, the packaged status2 selection retains openserver/scsserver/bt_device and omits the six zero-mode stack entries. These are conditional launch-call choices, not observed running/readiness claims.

All findings are static original-byte/control-flow analysis with a small host boolean selection model. ## The launcher’s actual selection and launch arguments

`selected-child-launcher.txt` preserves0x14dd0–0x14fb8. It obtains the list head, reads current working-status text **once** at0x14e18, then for each record:

1. Converts that saved status text with `atoi` at0x14e28.
2. If status equals2 **and** record+8 equals0, skips to next pointer+24 (0x14e30–0x14e60).
3. Otherwise builds four string arguments: two strings selected from tables by scheduler-policy field+16; decimal priority+20; and `path/name` from record+4/+0. The full scheduler table mapping is not yet decoded.
4. Adds terminating null and calls imported **`call_nowait` at0x14efc**. Its return is stored in record+12 at0x14f08 without an immediate success check, then formatted argument allocations are freed.

The exact current-status predicate is therefore `selected = !(status==2 && child_mode==0)`. It is **not** `selected = child_mode!=0`. No other status exclusions appear in this selected helper. Another specific-mode launcher0x148f8 compares child mode directly with its supplied argument and has separate PID/signal behavior; its saved partial span must not be substituted for0x14dd0’s predicate.
