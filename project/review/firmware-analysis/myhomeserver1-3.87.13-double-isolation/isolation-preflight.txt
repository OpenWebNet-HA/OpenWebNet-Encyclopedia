## Containment and finite call plan

- Image mappings derive from actual PT_LOAD offsets/extents. Code pages become RX, data pages read-only after the explicit canary setup. Guest writes cannot change image/canary/code or mapped-page padding.
- Each allowed original instruction must match exact PC, size and Thumb mode. Intercepted PLT boundaries require **ARM mode/size4**; private EXIT requires **Thumb mode/size2**. Original TBB bytes are read as data only. Unknown PC/import/size/mode, nonempty/error paths, IRQ, invalid instruction or protected/unmapped access stops with no success fallback.
- Guest stores are limited to the exact 24-byte private object or 64KiB stack. Reads require actual PT_LOAD extent or initialized private bytes. Imported UC_MEM_READ/UC_MEM_WRITE are used, and every other memory-hook event fails. The canary is four initialized read-only bytes. EXIT is intercepted before its placeholder instruction executes.
- Four fresh instances each have two manual entries: constructor then asDouble on the SAME original-produced object, no field reseeding between calls. Only call registers and a distinct D0 register poison are set for readback. The second call must leave object bytes unchanged, perform no object write and produce the selected integer bit pattern. No full JSON member/map/move/serializer/reparse operation is represented by these calls.
- The four finite bit-pattern cases and **eight planned entries are not executed coverage counts**. Per-entry original-visit, engine-count, engine-timeout, host-wall, normal-EXIT and balanced-stack checks are present. Counts explicitly mean code-hook visits, not retired instructions. Linker redirects, EXIT/guard boundaries, data relocation and FP/control setup are separate categories.
- Static preflight/check do not import Unicorn or reach emu_start. Explicit run first reproduces the exact frozen candidate, requires root approval binding harness/preflight hashes and independent-PASS flag, and refuses an existing RUN_STARTED marker. Only then can it import the verified analysis package, with bytecode disabled and an asserted-absent pycache-prefix path. No old firmware/harness is imported.
- Successful attempted calls are saved immediately/exclusively. Any guest failure retains completed and failed traces/counts and stops without retry; a post-instruction failure cannot be represented as execution zero. This review does not certify future execution results, unavailable pre-guest error outcomes or a security boundary against operators editing local files.
