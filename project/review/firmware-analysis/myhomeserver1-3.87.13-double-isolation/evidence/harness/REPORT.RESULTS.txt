# Isolated original JsonCpp double constructor/readback: canonical results

One root-executed, separately approved canonical run completed all four finite synthetic input cases. Each original `Json::Value(double)` constructor was followed by original `asDouble()` on the SAME constructor-produced private object, without field reseeding. The returned 64-bit double representation equaled the supplied representation for positive zero, negative zero, negative one and one-and-a-quarter. This is one eight-entry private helper corpus, not a full JSON serializer/member-assignment/reparse experiment or a firmware process run.

The root ran the exact frozen v3 harness once after both root and independent source-containment preflight PASS. This report's author performed only host saved-result/hash/source-ledger checks and did not execute another guest or replay. Root approval, run marker, every top-level attempt and immediate result snapshots are retained. No canonical guest failure or retry occurred.

The readback object bytes remain identical to constructor output and its write trace contains no object-field store. The integer-bit checks require no host floating computation.

These results narrow the original constructor/asDouble provider premise for these four supplied bit patterns. ## Binding, setup and containment limits

Actual original bytes are used, but the experiment supplies a private candidate binding: three intercepted ARM PLT entries redirect to their actual same-image Thumb definitions. These callbacks preserve execution of the original nested implementations; they do not prove live loader/interposition behavior. The sole selected synthetic GOT relocation points the original stack-canary checks to a fixed read-only private cell. It is not a target runtime secret or an observed target provider.

The original image pages were final RX/RO after setup; guest writes were restricted to exact 24-byte object storage and 64KiB stack. Original PC, size and Thumb mode were checked against 85 statically derived addresses; PLT boundaries required ARM/size4 and EXIT Thumb/size2. Embedded TBB data/literal pools were not guest PCs. Private stack read initialization and actual PT_LOAD read extents were guarded; unknown/protected/unmapped memory, IRQ, invalid instruction, nonempty Comments/error/other-type paths and limits would stop. Caps remained 5000 original visits per entry, engine count10000, timeout1 second and host wall2 seconds. The private code was neither an original target process nor an OS/service/network/bus invocation.

The analysis engine was Cortex-A15 with explicit CPACR/FPEXC/FPSCR/D8 host setup. Candidate ABI, empty Comments initialization and this synthetic storage/canary/register environment remain scope premises. No destructor, allocation/free provider, nonempty comment path, error/unwind or complete C++ lifetime was executed. No transport/authentication/session/framing/MQTT/libjel implementation or F454 firmware/layout/harness was imported. The historical F454-named directory supplied only the verified host Unicorn 2.1.4 analysis package.
