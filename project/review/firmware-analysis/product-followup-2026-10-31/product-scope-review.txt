## Existing research is the starting boundary

F454 run26/27 establish one staged normal alarm object through an explicit idle-state handler, monitor consumer, original callbacks/serializer and recorded10-byte send of `*5*17*#5##`. The selected software object/call path is concrete. The raw serial/internal producer, actual plugin/idle-state initialization, real subscription/readiness, physical bus origin and message destruction remain open. The one private subscriber and modeled send are not a capture or proof of delivery. The followup should close a new producer/ownership edge, not repeat the completed zone/serializer cases or relabel their synthetic raw input as physical alarm traffic.

MH202 native taskmanager WHO17 ownership is distinct from COSO's WHO0 scenario translation. Its loader tests numeric1..300 across failed opens; the PHP index stops at the first empty scenario name and sends its separate XMLid. Native `.spt` paths, info.xml metadata and the source-view expression cannot be assumed mutually complete or valid on a running product. The supplied package lacks referenced2.xtz/4.xtz and mounted extra contents. A newly found artifact may narrow this, but filenames/path coincidence, catalogue Extra XML associations or missing root-image descendants alone cannot prove a generator/schema, installation layout, global artifact absence or full accepted script grammar.

The already reviewed interpreter/FIFO work is conditional source behavior, not actual configured source-to-action execution. New artifact evidence should state whether bytes are manufacturer package content, Suite configuration output, a supplied project, documented example or host reconstruction. Report exact provenance and which caller consumes it. Do not invent missing configured scripts from manual examples or treat a finite host grammar model as a real artifact.

## Integration acceptance checks

1. Keep documented product purpose/connector legends and catalogue roles separate from new build-specific code findings; cite the exact original path/VA/field and remaining edge.
2. For F454, name whether ownership is logical lane, daemon, UART/internal envelope or electrical connector; stop at the precise missing mapping rather than assuming all are synonymous.
3. For MH202, preserve alarm reaction-only scope, scenario Module61 and missing configured resources. Any artifact conclusion needs its own exact source/identity and producer-consumer correspondence.
4. Keep software publication, local API receipt, serializer output and physical delivery distinct. No new installed state, public support/grammar, physical topology, full-source coverage or cross-build behavior follows from names.

The current Device/manufacturer reconciliation supports these investigations without requiring a new feature claim.
