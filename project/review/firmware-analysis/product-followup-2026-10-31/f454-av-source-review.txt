## Findings and exact conditions

The selected WHAT helpers do not conflate a base command and its parameter. `0xc044` clears seven 30-byte temporary buffers and tail-calls the splitter for nonempty input. Its splitter copies the first `#` token into the base slot, advances from the original input by token length plus one, requires the following substring to begin with an ASCII digit, and copies its next token into the first-parameter slot. Base getter `0xc0f0` returns atoi of `0x2b6a1` or -1 for empty; first-parameter getter `0xc11c` returns atoi of base+30 or -1 for empty. This relies on compatible input strings and ordinary strtok/copy/atoi contracts; it is not a full or malformed raw-input grammar assessment.

In the role1 caller, `0x14554..0x14558` calls first-parameter getter and retains its result in r5. `0x14574..0x1457c` calls base getter and retains its result in ip, including explicit stack save/reloads across clobbering calls. The selected normal-dispatch route preserves r5 into WHAT37 branch `0x15d24`. Destination conversion at `0x15d44` must return other than -1 before the selected stores. Comparisons at `0x15d58`, `0x15d6c`, `0x15d7c` admit only first parameters 1, 2, 3 to the shared local store at `0x15d9c`, which writes r5 to the global. Other local parameter cases branch away from this store. This is a valid conditional static writer finding.

The original predecessor gives a stronger concrete limitation than merely assuming normal dispatch: on the selected WHO8 normal path, `0x14624..0x14644` diverts write/measure frames, and `0x14648..0x14654` requires the existing global value to equal 2. The later WHAT37 special cases do not bypass that earlier guard. Thus this role1 branch does not by itself prove how a startup -1 role1 first reaches 2, or how an arbitrary deployed device becomes available. The author already conditions its finding on earlier admission and reaching normal dispatch, so this is an explicit source-review premise rather than a correction to a claimed unconditional route. Other initializations, roles, aliases and unexamined callbacks remain outside the finding.

Role2 is a distinct caller. Its first WHAT parameter is retained in r8 at `0xf280`, base WHAT in ip at `0xf2a4`, with stack reloads across calls. The intervening `0xf310..0xf36c` computes an admission flag, and `0xf3f8..0xf408` requires WHO8 and the flag low bit before reaching the selected WHAT37 dispatch. Under that route and destination-helper result not -1, selected parameter 1 stores at `0xf940`, 2 at `0xf9c0`, and 0 at `0xf9ec`. These do not define a universal command acceptance table, shared role1 policy or physical-state meaning.

Constructor `0xdad4` pushes two words, loads the caller's fifth ABI argument from new SP+8 and writes it to the global at `0xdaf4`. The selected configuration-role2 and configuration-role1 startup paths pass stack argument -1. Configuration+32's selector is not thereby the same object/namespace as any constructor record field or the global. Role5 is selected separately by the comparison at `0x1d870`. Its preceding `0x1d878..0x1d888` initializes the 128-byte output buffer before the imported getter, but does not prove arbitrary provider behavior or all errors preserve empty text. The actual nonempty and empty branches both call the constructor with fifth argument -1 and then override global to 1 at `0x1d910` or `0x1d954`. The configured atoi result or default 24 is stored at record+32, a different location and quantity.

The two host ledgers supply already selected branch premises and describe assignments only. They do not exercise original parsers, destinations, allocation, callbacks, imports or natural startup. The single-ELF aligned-word/encoding query is appropriately described as a bounded candidate search, not all-writer or all-alias analysis.
