# F450, F453AV, F455, F459 and MH200N firmware and databases

This build-specific study records six retained packages across five product families. It connects selected configuration, resource and database request paths while keeping original data, inferred format, software requests and observed operation separate. The current snapshot covers the first exploration and six bounded overnight batches; research remains in progress. No Firmware, target process, native helper, emulator, SQLite query or Physical Device was executed in this study.

The [evidence capsule](../../project/review/firmware-analysis/remaining-firmware-2026-11-01/README.md) preserves exact selected reports, collectors, source metadata, independent reviews and archive receipts. It also records which original inputs and complete histories remain local; exported collectors alone are not a self-contained execution package.

The [run05 continuation](../../project/review/firmware-analysis/remaining-firmware-run05-2026-11-01/README.md) adds conditional startup-file aliasing, an independently mapped recovery-entry request and a shared-store namespace source. Earlier evidence and historical input versions remain separately retained.

The [run06 continuation](../../project/review/firmware-analysis/remaining-firmware-run06-2026-11-01/README.md) adds permitted resource-caller, independent recovery selection and local teardown request evidence, preserving the earlier snapshots and their limits.

## Database evidence and private preservation

The first survey checked offset-zero prefixes of 16,088 extracted regular files and found no SQLite 3 magic. This does not rule out embedded, encrypted, archived, configured or runtime-created databases. One `Thumbs.db`-named candidate has an OLE header; it is not established as an application catalogue. Structured file paths and a SQLite library are leads, not recovered schemas. No SQLite query was run, and an unused host parser/helper is not a tested contract. [Initial reports and review](../../project/review/firmware-analysis/remaining-firmware-2026-11-01/README.md#source-navigation) preserve this bounded survey.

F450 PROD contains the original encrypted `50.xtz` support container. Its archive metadata declares `50/master.sqlite`, but plaintext database bytes, header, schema and rows remain unrecovered. The original 72,774-byte container has SHA-256 `824b9b224689afa75d27d5271cbb812d18d0a13915696f1404d21500191bf9d8`. It was archived privately as supporting data, not as a decrypted database. The [actual archive receipt](../../project/review/firmware-analysis/remaining-firmware-2026-11-01/archive-receipt.json) and [classified archive index](../../project/review/firmware-analysis/remaining-firmware-2026-11-01/archive-index.json) record one encrypted support object and zero plaintext database objects. The configured uploader's success follows its full readback SHA-256/size check; later source reviews did not independently replay that network operation.

SQL declarations were never used to manufacture a database and call it a vendor original. Any future recovered database requires its own format identification, original-byte provenance and content deduplication. A modern SQLite 3 parser is not a substitute for SQLite 2 or Berkeley DB identification. Private values, credentials, keys and full Configuration data are outside the published evidence.

## Selected implementation contracts

### F450: configuration and archive requests remain distinct from extra50

One selected local path requests copying a named `master.sqlite` to a temporary database path and passes the same destination to a SQLite-open helper. The selected open-result gate and subsequent SQL request do not prove that a file was copied or opened. [Database consumer evidence](../../project/review/firmware-analysis/remaining-firmware-2026-11-01/packets/run01-f450/REPORT.txt) retains provider and admission premises.

A separate supplied context reaches an argument-vector-shaped unzip request under a numeric field gate. A packaged candidate wrapper forwards the request to an opaque launch helper, requests waiting and returns a selected status byte. These are source requests, not extraction or process-success observations. [Request handoff](../../project/review/firmware-analysis/remaining-firmware-2026-11-01/packets/run03-f450/REPORT.txt) keeps the actual caller and binding limits visible.

The registered text-callback path now provides a positive configuration producer: selected `db_name` text and length reach a duplication request whose result is stored at context field76; selected `db_compressed` text reaches a numeric conversion request whose result is stored at field80. Those are the fields consumed by the earlier request path. Valid markup state, callback ABI, live binding, unchanged owner and normal provider returns remain premises. The initialized temporary configuration pathname and the packaged configuration file are different evidence roles. The packaged file has separate `extra/enable` and `extra/check50` declarations; no source relation to the two fields or an effective archive input is established. [Configuration producer](../../project/review/firmware-analysis/remaining-firmware-2026-11-01/packets/run04-f450/REPORT.txt) therefore narrows the source gap without recovering a decoder, packaging key or database.

The selected original startup configuration also declares a link from the daemon's initialized temporary markup pathname to the packaged configuration. Its actual population script conditionally requests that link; existing files or links, cache selection, asynchronous completion, shell/tool binding and startup admission remain premises. This narrows the file-origin gap, but establishes neither an effective live alias nor `db_name` content, extra50 association or decrypted database. [Startup alias evidence](../../project/review/firmware-analysis/remaining-firmware-run05-2026-11-01/packets/f450/REPORT.txt) keeps the metadata declaration, script request and observed filesystem state distinct.

An original application caller also supplies two compiled resource-path pointers to an opaque local request: a temporary configuration pathname and a relative BACnet template pathname. Its returned machine word selects a local return or logging/exit requests, without establishing parser success or failure. Actual working directory, live path resolution, file bytes, reading/parsing, template activation and complete error policy remain unresolved. [Resource-caller evidence](../../project/review/firmware-analysis/remaining-firmware-run06-2026-11-01/packets/f450/REPORT.txt) adds the original argument and return-gate edges beyond the earlier filename census; the helper body remains unexamined.

### F459: a shared-store request is not durable state

The original constructor connects a concrete database-path literal and receiver handle field to SQLite-open, busy-handler and table-creation requests. The SQL declares `pluginname`, `key`, `value` and `persistent` fields. The selected write path requests Latin1/Base64 conversions for three supplied strings and decimal conversion of an integer before SQL substitution. The integer supplies the fourth, `persistent`, placeholder under ordinary object, ABI and provider premises. A later selected fragment tests the retained middle SQL result rather than the later request's result. [Constructor](../../project/review/firmware-analysis/remaining-firmware-2026-11-01/packets/run01-f459/REPORT.txt) and [write evidence](../../project/review/firmware-analysis/remaining-firmware-2026-11-01/packets/run02-f459/REPORT.txt) do not establish accepted values, transaction success or durability.

The selected read entry distinguishes a supplied output pointer from the receiver and key. It prepares a two-placeholder lookup, tests a later step result against numeric100, and on that selected branch requests column0 text, byte-array construction, Base64 decoding and ASCII conversion before a local output store. Another selected result branch constructs an empty representation. Actual rows, successful reads, lossless roundtrip, complete error handling, natural caller, effective schema, freshness, ownership and concurrency remain unresolved. [Read evidence](../../project/review/firmware-analysis/remaining-firmware-2026-11-01/packets/run03-f459/REPORT.txt) retains the exact argument cells, result gate and provider boundaries. The separate legacy SQLite library and SQLite 3 imports are not treated as the same database format or effective provider.

A selected constructor prefix now identifies where the query's first string can come from: a relocated external global-symbol address is dereferenced to a pointer, and its field at offset24 supplies a string-assignment request into the same receiver's field12. Valid initialized objects, effective binding, ordinary assignment and no later invalidating mutation are premises. The global's definition, field meaning/value, lifetime and natural caller remain unresolved. This is a conditional query-namespace source, not an installed plugin identity, uniqueness or isolation claim. [Namespace-source evidence](../../project/review/firmware-analysis/remaining-firmware-run05-2026-11-01/packets/f459/REPORT.txt) separates the symbol address from its loaded pointer and preserves the two inherited query-operand spans as context only.

Selected teardown source places a SQLite-close request before a watcher-destruction request in its local normal path. The close result is overwritten before a later member-field comparison. A separate deleting-destructor export requests destruction and then deletion using the same supplied receiver. Valid objects/handle, binding, intermediate cleanup, normal returns and lifetime remain premises; natural last-owner ordering, actual closure, callback quiescence, durable commit and concurrent safety remain unproved. [Teardown evidence](../../project/review/firmware-analysis/remaining-firmware-run06-2026-11-01/packets/f459/REPORT.txt) distinguishes local request order from completed shutdown or a global failure policy.

### MH200N and F453AV: resource and module requests need their own environment

MH200N's selected startup branch changes retained resource-path cells; a later source join passes the selected path into a local reader. That reader requests an open and a 1024-byte read, then tokenization with an exact delimiter. Subsequent source requests pass one nonnull token to a compiled destination. Descriptor validity, terminated data, tokenizer state, destination capacity, ordinary providers and surrounding admission remain premises. Local numeric returns and string-copy requests do not prove complete resource grammar, field meaning, application installation or a current partition. [Path context](../../project/review/firmware-analysis/remaining-firmware-2026-11-01/packets/run01-mh200n/REPORT.txt), [reader](../../project/review/firmware-analysis/remaining-firmware-2026-11-01/packets/run03-mh200n/REPORT.txt) and [selected token destination](../../project/review/firmware-analysis/remaining-firmware-2026-11-01/packets/run04-mh200n/REPORT.txt) remain separate bounded contracts.

F453AV's normal startup source loop conditionally reaches its own module-load script and packaged module metadata. The recovery script differs even where selected module and loader bytes match. Actual loading, kernel compatibility, video availability, readiness and ordering with the application starter remain unproved. [Normal-image module evidence](../../project/review/firmware-analysis/remaining-firmware-2026-11-01/packets/run02-f453av/REPORT.txt) supplies no normal-to-recovery or installed-overlay equivalence.

F453AV's own recovery image has a separately mapped entry that supplies a compiled candidate main pointer to an actual `__libc_start_main` import request. The prior script and header facts are inherited context; the new edge does not inspect the candidate main body or prove that startup runs. Loader, entry-state, provider ABI and natural recovery admission remain premises. [Recovery-entry evidence](../../project/review/firmware-analysis/remaining-firmware-run05-2026-11-01/packets/f453av/REPORT.txt) does not transfer normal-image module behavior or imply an installed recovery environment.

Within F453AV's own recovery candidate main, a compiled file-request pathname reaches an exact numerical negative-one test. The selected other-result leg stores one compiled resource-path pointer into a writable cell. Current flag value, intervening opaque returns, object/storage validity and recovery admission remain premises. This independent source does not transfer MH200N marker semantics or establish a valid descriptor, marker truth, active partition, copy or installation. [Recovery resource-gate evidence](../../project/review/firmware-analysis/remaining-firmware-run06-2026-11-01/packets/f453av/REPORT.txt) stops after that single assignment.

### F455: retain a format hypothesis without assigning a target

Original wrapper, XML and CRC evidence identify the retained raw payload. A finite prefix and explicit hypothetical-base arithmetic support a vector-shaped M-profile/Thumb-compatible candidate. One pinned official Arm document supplies pattern context only. Actual endianness, CPU, ISA, ABI, load map, vector extent and entry behavior remain unproved; no architecture was forced into a disassembler. [Format report](../../project/review/firmware-analysis/remaining-firmware-2026-11-01/packets/run02-f455/REPORT.txt) explains the original-byte relationships and their limits. Authoritative loader, linker or manufacturer provenance is needed before following code.

## Evidence limits and next work

The [coverage](../../project/review/firmware-analysis/remaining-firmware-2026-11-01/coverage.txt), [ranked questions](../../project/review/firmware-analysis/remaining-firmware-2026-11-01/remaining-questions.txt), source reviews and saved checks retain the snapshot's unresolved boundaries. Natural Configuration producers, active assets, full JSON/XML/SQL behavior, effective providers, type/ID/freshness, complete errors/unwind, ownership/concurrency and physical effects remain open. Closed receiving, output-transport, authentication, session, framing and MQTT/libjel implementations remain unexpanded.

Static source reasoning, host extraction/identity checks, isolated original-helper execution, complete runtime and Physical Device observations are different evidence levels. This study adds only the first two. Earlier MyHOMEServer1/F454/MH202 ledgers remain separate and unchanged, with no replay accumulation; unavailable MH202 run18/run21 intermediate histories remain unverified. Source/header/word agreement and several reports about the same instructions are not independent physical corroboration.
