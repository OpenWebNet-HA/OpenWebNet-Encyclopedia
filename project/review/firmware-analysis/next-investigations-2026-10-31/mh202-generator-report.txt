# ScenarioSuite database-to-script method chain - static source

The recovered original assemblies contain a concrete compiler chain, not just script-name literals. DataManager owns the rule-query builders; Core owns their row conversion, ordered OPEN-field substitution, scenario-line construction and actual file/XML API call sites. `cCore.CompileAll` passes a scenario-specific `.spt` pathname to `cCompiler.CompileScenario`, whose original method constructs a StreamWriter and writes the built line list; CompileAll also constructs and saves `info.xml`.

These are original method/token/IL dataflow findings. No vendor assembly, reflection instruction, compiler, SQLite driver, project, script or firmware was executed. No fixture scenario or fabricated SQL object was supplied. The finding identifies an available source implementation; successful generation, configured inputs, complete language behavior, installation and compatibility with MH202 firmware1.0.24 remain unproved.

## OPEN rule to command support

`MakeOpenCommand` calls original `GetOpenParameterObject` at IL0092, then `cCore.GetOPENRuleCompile` at IL00b8 with CommandIn.IDOBJ, ID_COSA and IDArea. On its selected successful path it iterates returned rules and fields1..10, obtaining `OPEN_FIELD_n` properties through original metadata-named reflection call sites. It recognizes ID_CHI, ID_COSA and ID_DOVE substrings and substitutes the resolved WHO/WHAT/WHERE components; other nonempty fields are appended as literal template content. The selected concatenation uses `*` between fields and wraps the result with leading `*` and trailing `##` at IL0315..0325. It assigns that constructed value to `cCommandSupport.MakeOpen` at IL0346, alongside its separate Who/What/Where values. Object-specific later normalization branches also exist; no universal substitution/escaping contract is claimed from this selected description.

`GetOpenParameterObject` actually calls Core WHO/WHAT/WHERE-related consumers, not an analyst-supplied placeholder dictionary. It also has custom/configuration/auxiliary paths and unexpanded generic/LINQ calls. Those details remain boundaries: no selected Counter/Boolean object or custom range was run through the method, and no method-specific result for the temperature/time-labelled range reuse is inferred here. Generic signatures and underlying token references are preserved without inventing decoded generic type semantics.

`CompileScenario` calls MakeOpenCommand at several area-specific sites, stores the command support objects and builds its line list. The ordinary script includes command strings/variables and control/header templates; OWRITE consumes a script variable on the selected later path rather than establishing that every emitted command line directly embeds a literal frame. This is a static source value/call relation, not a generated or executed `.spt` example.

## Actual script and index writer call sites

Core `CompileAll` takes named parameters ScenariosCollection, AllCompiled, OutputFolder, CompileAllAction and WhichScenario. The selected compile branch enumerates supplied scenario objects and reads their original ID. IL016c..017d builds `Path.Combine(OutputFolder, ID + '.spt')`; IL0187..0199 then builds `Path.Combine(that path, ID + '.spt')`. These are a scenario-specific directory and nested script pathname in this method. They are not silently flattened to a deployed firmware filename. Different action/mode selections and errors can skip compilation or change subsequent output handling.

On the selected branch, IL027c..0287 passes the actual scenario, Core, nested FileSPT pathname and output references to `cCompiler.CompileScenario`. The compiler's named FileSPT parameter is used for the script-name header and, at IL3a41..3a48, `new StreamWriter(FileSPT, false)`. The original loop rewrites specific line placeholders, then calls referenced `TextWriter.WriteLine` at IL3b6b and closes the writer at IL3b8d. Error handlers/regions are retained in evidence; existence of call sites does not prove an actual successful file write. The earlier caller can delete `.spt` output and write `.err` when compilation status/action-count conditions fail.

CompileScenario has explicit header/control templates, including `$NOMESCRIPT`, `$RESTART` with SI/NO from Scenario.Restart, BEGIN, END, IIF, GOTO, OWRITE, SLEEP and SLEEPRANDOM. Scenario.Repeat selects a later branch that uses a stored BEGIN line number in a GOTO-format line before END. These are original compiler source choices, not proof of the firmware's full repeat/restart or panic lifecycle; no specific scenario values or output lines were fabricated.

CompileAll separately constructs an XML document rooted `script`, creator software data and panic/scenario entries. Its per-scenario nodes include name `ID.spt`, numeric id, user description and scen_name. IL057e..0589 constructs `Path.Combine(OutputFolder,'info.xml')`; IL059f..05a3 calls original referenced `XmlDocument.Save` with that path. This establishes ownership of the index writer, distinct from load/copy methods that also reference info.xml. Actual runtime XML serialization, installed contents and a successful project export remain unobserved.
