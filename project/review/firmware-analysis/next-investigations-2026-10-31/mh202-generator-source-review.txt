## Critical source conclusions

* DataManager06000030 at RVA0x4690 owns the seven area selectors3..9, SQL literals and catalogue connection field. IL001c subtracts3 before the switch; the cases select start/condition/action/stop/enable/disable/panic flag names. IL00c8..0112 constructs the object/flag/command filter. IL0169 calls the referenced adapter Fill; IL018b..0198 adds the named table only when its returned count is greater than0. The selected normal tail returns1. This is method-level filtering/provider use, not live provider success or complete UI permission precedence.
* Core060000bd at RVA0xe408 calls the manager at IL002a. The boolean selection sequence `0,cgt.un,neg` is followed by comparison with-1. Direct original raw bytes at IL0036 `4099000000` calculate targetIL00d4; IL0052 `2c7c` targetsIL00d0; IL00d2 `2b08` targetsIL00dc. Thus manager0 reaches local return-3, whereas the selected normal manager1/missing named-table route sets fallback1 and reaches default constructionIL00f8. Header size12 is excluded from report IL coordinates; dncil's stored body-relative branch target includes it. There is no branch-direction inversion in the final report.
* Core06000021 at RVA0x61ec calls06000022 at IL0092 and060000bd at IL00b8 using command object/command/area properties. Its successful local result0 path enumerates returned rules, constructs OPEN_FIELD_n property names, inspects their values, substitutes ID_CHI/ID_COSA/ID_DOVE and concatenates fields before selected `*`/`##` wrapping and MakeOpen assignment. Reflection API names are source call operands only; no reflection was executed. Additional object-specific branches prevent treating this as a universal escaping/format contract.
* Core0600001f calls the status consumer at IL05b3. The original EXTRACTVALUE format at IL1947 and actual argument-array stores select ReplyDimension via06000060 at IL197b and ReplyPar via06000062 at IL1986. This establishes declaration-to-template source ownership. It does not establish the firmware reply parameter indexing convention, returned status or a real condition evaluation.
* Core060000c8 at RVA0xfba0 reads the supplied scenario ID and uses two actual Path.Combine calls: IL016c..017d builds OutputFolder/ID.spt, then IL0187..0199 builds that directory/ID.spt. The selected action/control branch passes this local pathname as CompileScenario's FileSPT argument at IL027c..0287. The compiler later loads argument3, false and `new StreamWriter` at IL3a41..3a43, iterates the line list, applies selected placeholder replacements, calls WriteLine at IL3b6b and Close at IL3b8d. The caller can instead skip compilation, or delete script output/write an error file following nonzero compile result or empty Execute list. Writer API ownership is proven; successful filesystem output is not.
* CompileAll separately constructs the script XML nodes. The scenario sequence counter names `scenario_n`, while the scenario object's actual ID supplies name `ID.spt` and id fields. UserDescription/Name supply description/scen_name. IL057e..0589 combines OutputFolder with info.xml and IL05a3 calls referenced XmlDocument.Save after a selected existing-file deletion branch. This is an actual index-writer source join, not mere reuse of an info.xml literal or a claim that a deployed file was observed.
