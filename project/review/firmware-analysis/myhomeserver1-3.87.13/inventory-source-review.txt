## Reproduction and independently checked evidence

The unmodified collector's read-only `--check` passed all13 outputs. I inspected the collector and metadata-only ImageVFS: reads require regular-file metadata and expected size/SHA, reject host symlinks, use read-only descriptors and original-image link metadata. SQLite author connections use immutable read-only URI plus query_only; this review also set trusted_schema=OFF in its separate connections. Neither method runs vendor expressions, original applications or target libraries.

I independently read the prefix of every retained ordinary file and directly decoded saved ELF header fields from original bytes. Results agree: normal5924files =858ELF +1SQLite3 +5065other; recovery5384 =740ELF +1SQLite3 +4643other. The selected ZIP-local-header and REDIS prefixes have no matches. This is the exact named prefix/extension scope, not global absence of storage or container contents. All1598 original ELF header records' path/size/manifest identity, class and applicable ARM32 type/machine/entry/flags agree. Selected matrix_mx interpreter/Thumb-entry interpretation and hard-float EABI fields agree with its original header. No uniform ABI claim for all ELF roles is made.

I separately recomputed the original manifest path intersections:5378 shared,5368 equal,10 differing,546normal-only and6recovery-only. I re-read the eight selected application's dynamic declarations and independently compared every saved DT_NEEDED/import-name set. Original matrix_mx contains one exact `MHCatalogue.db` literal at file offset0x1cce04, independently mapped through its PT_LOAD headers to VA0x1cce04. Its undefined dynamic symbols include sqlite3_open, open_v2, prepare_v2, step and exec. These facts justify the report's candidate-consumer lead. They do not trace a literal-to-path-to-open call chain, prove an executed read, or identify an active scenario owner; the report expressly leaves those open.

For both database files I independently compared the complete stored CREATE TABLE strings and all75 complete typed row bags using direct Python Counter tuples, rather than relying only on the author's serialized digest equality. All75 table names/schema strings agree;42 row bags match and33 differ, with exactly the saved complete table partitions.
