## DIM56/510 and persistent buffer rules

At0xd968–0xd980 the selected FD0x50 rows0x10..0x14 reach0xe544. WHO is set18; the WHERE string is reconstructed; **dimension text is `5%d` with `(numeric row−10)`**, formatted at0xe5a8–0xe5b4. Thus hexadecimal rows10,11,12,13,14 (decimal16..20) give dimension strings **56,57,58,59,510**. This is text concatenation, not the arithmetic mapping used for newer dimensions511–514. Row0x16 has an independent special DIM52 choice.

For the selected rows:

- On accepted data record1, row0x10 additionally takes raw[13:15] as second metadata at0xe85c–0xe874. Row0x14 retains header metadata2=−1. The code takes raw[15:17] and raw[17:19] as two hex bytes, converts each to decimal and **replaces** the persistent buffer with `%d*%d` at0xe6c0–0xe704.
- On later records, the ordinary row path takes all three bytes raw[13:15], raw[15:17], raw[17:19]. For selected rows0x10/0x14,0xe76c compares row0x19 and0xe770 branches to0xe7f0 on mismatch. This path loads **`%d*%d*%d`** at0xe840 from pool0xe928 and sets the destination to **context+820** at0xe850, then calls `sprintf` through0xdd00. It **replaces** the buffer with the three current decimal values. The `strlen`/end-pointer append path0xe774–0xe7ec and leading-star format0xe9b0 belong specifically to row0x19 and are not used by these two selected rows. Values are individual bytes, not a single24-bit quantity or newly established Wh readings.
- If the remaining countdown is nonzero,0xe404–0xe420 selects this old-row intermediate path. The formatted frame contains the **current record's decimal buffer**, first metadata, optional nonnegative second metadata, and accepted-record counter. It does not accumulate prior records' scalar values.
- At countdown0, control goes through0xdd04–0xdd38 to a **separate terminal record rule**. Row0x10 takes0xddc0–0xddf8 and replaces the buffer with the first two current record bytes as `%d*%d`; row0x14 follows the original jump-table entry0xdd5c→0xde00 and replaces it with only the first byte as `%d`. This overwrites the temporary three-current-value buffer. The terminal frame is another selected record representation, not a replay of prior values.

The terminal rule may encode a different record role, but this code alone does not establish it. In particular the first/two/three-byte variants are not assigned date, sample, tariff or physical sentinel semantics here, and the final overwrite is not labelled a defect.
