# Run25 — native sender failure, reset and remaining-output policy

## Finding

For the selected original WHO0 sender, a first write return of −1 or 0 causes the original library helper to return −1. The original sender calls close for its private descriptor 42, sets both its local descriptor and client field+24 to −1, skips the second output's write, and executes the deleting destructors for **both** output objects. The sender still returns 0. Its original transaction/consumer then completes cleanup and next-batch reset under the existing fixture.

A short-positive return 1 for a 10-byte request follows the helper's success branch: no retry of the remaining 9 bytes, no close, and the next request is the separate full second frame. A failure on that second write closes/reset the descriptor after the first request. These are original caller/helper decisions under explicit record-only return fixtures, not observed delivery, data loss, hardware failure, exploitability or actual connection behavior.

## Two different result layers

Original library VA `0xc3d8` calls write. At `0xc3dc` it compares the returned value with 0, and `0xc3e8` branches on signed ≤0 into failure. The original failure tail `0xc42c..0xc43c` logs and returns−1. Positive values reach `0xc3ec..0xc3fc`, which return 1; this selected helper path does not compare against requested length or retry a remaining tail.

Original `bt_luci` `0x18390` calls that helper via PLT `0xb984`, bound privately to actual `libcommon` `0xc348`. Original `0x18394..0x183a4` tests the **helper** return and branches on nonnegative into its normal path. The helper returns 1 or−1 in these fixtures. A hypothetical helper 0 would take the nonnegative caller branch by static code, but no helper 0 is injected here; the zero-write case actually executes the native library's−1 return.

The negative branch executes original `0x183a8..0x183e4`: logging, `0x183d8` close call, `0x183dc` local descriptor−1, `0x183e0` client+24 store−1, then branch to current output cleanup `0x18414`. No original reconnect helper is called on this selected mode 2 error tail. Later connection acceptance/readiness is outside this run; this is not a claim of permanent disconnection or absence of future recovery.

At the next item, original `0x18374..0x18378` sees its local descriptor−1 and branches directly to cleanup. It does not invoke `invio_msg_open` for the second item. Original code continues native vector iteration, rather than returning immediately upon the first failure or retaining the second object for retry in this batch.
