# F454 2.0.51 Firmware Analysis

This analysis concerns the identified BTicino F454 Firmware archive, not every F454 installation or the complete OpenWebNet protocol. It adds selected implementation evidence to the [audio/video web server and gateway definition](../../devices/definitions/own-dev-0002-audio-video-web-server-gateway.md). The archive remains private; analysis reports and derived facts are retained separately.

## Build composition

The kernel configuration selects TI DaVinci DM365, BASI, ARM926T/ARMv5, ARM EABI and no VFP support. The kernel banner identifies Linux `2.6.32.17-davinci1-c44221b9cd7e82d5ec494320685310d138f4dd07` and GCC `4.8.2`. These are build-target facts, not a new hardware interrogation. Kernel configuration locators include lines `205`, `211`, `233..234`, `277` and `324`; the [platform excerpt](../../project/review/firmware-analysis/f454-2.0.51/platform-report.txt) records the original extraction and checks.

## Reconciliation and remaining integration

The Device page's earlier statement that the package payload was unexamined is superseded for the incorporated paths. Its catalogue records and official-document release history remain separate evidence; no new catalogue Firmware row is inferred from the archive label.

This first integration does not promote the complete local research dossier. Authentication/session details, functional command matrices, energy history, full web ownership/exception paths, update/recovery transitions and remaining diagnostic routes still need reconciliation against their canonical pages. The existing [WHO 25 gateway comparison](../../project/review/who25-gateway-compatibility.md) is separate firmware-oracle evidence and has not been rerun or replaced here.

Concrete unknowns include persistent `p7`/optional extra assets, production provider initialization, actual subscriptions and transport recovery, allocator/thread behavior, real exception unwinding/HTTP completion, update authenticity/power-loss/durability, WHO 17 attribution, VDE activation, energy units/calendar/provenance and raw temperature values `501..511`. These cannot be closed by assigning convenient meanings to implementation names or synthetic inputs.
