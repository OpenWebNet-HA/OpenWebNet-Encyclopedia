## Old energy frame to consumer

The selected `api-arm` DIM56 and DIM510 mappers preserve the dimension/date text in JSON `date` and the record identifier plus following values in string `extraValues`. They select `getHourlyConsumptionValuesOldDevice` or `getDailyConsumptionValuesOldDevice`. The packaged `ConsumptionProductionFamilyModel.js` maps those event names to dedicated old-device handlers. This is a concrete schema join to the [per-record producer](f454-2.0.51-continuation.md#old-format-energy-producer), separate from newer DIM511..514 and the direct-DH candidate.

| Consumer | Selected source behavior |
| --- | --- |
| DIM56 hourly | Match the selected UI month/day. Record1 uses the second payload value; records2..8 place three values each; record9 places two values and a totalizer high byte; record10 adds the second payload value as the low contribution |
| DIM510 daily | Match the selected UI month. Cases1..21 reconstruct high/low byte pairs, carrying partial pairs across records; there is no case22 |

These are F454 web-client rules, not replacements for the [historical touchscreen decoder](../../functional/who-18-energy-management/dimensions.md#legacy-graph-values-and-unavailable-data). The selected F454 daily pair decoder zeroes individual `255` byte values before arithmetic. Hourly scalar fields have similar replacements; the record9 totalizer high byte is a separate unnormalized field. The touchscreen's paired-value rule only zeroes the complete `255*255` pair. Neither policy establishes a universal wire sentinel or physical measurement unit.

The F454 hourly array starts with 24 zeros. The selected record sequence writes index0 and indices2..24, leaving index1 at its initial zero and extending the array to 25 elements. That zero is initialization state, not a received zero measurement. The daily handler's explicit cases and byte reads also prevent treating every shortened terminal record as a complete sample: a one-value terminal record21 does not supply all three values that case21 reads; a separate record22 has no case in this handler.

The old handlers have no year gate. The daily model and graphic view also use different date-selector classes, so a model update is not itself proof of a visible graphic update. The host reconstructions illustrate these source consequences under declared record counts, selected dates and ordered delivery. They do not establish actual stream lengths, calendar-dependent termination, live data loss, missing-packet recovery, browser rendering or a physical Firmware defect. The producer's terminal widths are now linked to a concrete consumer, but full producer/consumer compatibility still needs actual traffic and runtime state. See the [consumer report](../../project/review/firmware-analysis/f454-2.0.51/final-pass-energy-report.txt) and [host examples](../../project/review/firmware-analysis/f454-2.0.51/final-pass-energy-model.json).
