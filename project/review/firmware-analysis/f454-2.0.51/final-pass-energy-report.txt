## DIM510: cross-record byte pairs and the shorter-terminal limit

The daily old handler's explicit switch at lines208–375 reconstructs two-byte quantities as `256*high+low`, replacing individual string255 values with0. It has cases **1–21**, no22 case and no general terminal-record padding. The layout is:

- Identifier1 has two payloads, establishing array index0 from high/low (210–215).
- Even identifiers2..20 have three payloads: complete the next high/low pair, then store the next day's high-byte partial (e.g.case2 at216–223; case20 at360–367).
- Odd identifiers3..21 have three payloads: add the first low byte to the preceding stored partial, then establish a complete following high/low pair (e.g.case3 at224–231; case21 at368–375).

The model calls these positions day1..31 because that is how the actual frontend array and variable names use them.
