# Legacy gateway Firmware and application data

The inspected F450, F453AV, F455, F459 and MH200N packages expose different application and data roles. F450 source connects configuration fields to archive/database requests; F459 source describes a local shared store; MH200N source contains selected scenario-file consumers. These implementation findings do not establish an installed Configuration, successful storage or physical operation.

## Database evidence and private preservation

No plaintext application database was recovered from these selected packages. F450 PROD contains original encrypted `50.xtz`; central-directory metadata names encrypted `50/master.sqlite`. This supplies neither plaintext header/schema/rows nor a demonstrated decoder. The preserved container is supporting evidence, not a decrypted database.

The [database source reference](remaining-firmware-database-handoff.md) separates actual original bytes, format signatures, library presence, compiled SQL and runtime-created stores. ## Selected implementation contracts

### F450: configuration and archive requests remain distinct from extra50

A selected local path requests copying named `master.sqlite` into a temporary database path, then passes that same destination to a SQLite-open helper. Its open-result gate and SQL request do not prove successful copy, open or query. [Database consumer evidence](../../project/review/firmware-analysis/remaining-firmware-2026-11-01/packets/run01-f450/REPORT.txt) retains the local argument and result channels.

A separate archive request uses two context fields: selected `db_name` text reaches a duplication request stored at field 76, and `db_compressed` reaches numeric conversion stored at field 80. A gated caller supplies the former to an unzip-shaped argument vector. A candidate wrapper delegates launch/wait operations and returns a selected status byte; that byte is not certified process success. Composition requires valid markup/callback state, the same unchanged owner, effective binding and normal returns. [Configuration producer](../../project/review/firmware-analysis/remaining-firmware-2026-11-01/packets/run04-f450/REPORT.txt) and [request handoff](../../project/review/firmware-analysis/remaining-firmware-2026-11-01/packets/run03-f450/REPORT.txt) identify these fields.

Startup configuration conditionally links the temporary markup pathname to a packaged file. Existing files/links, cache selection, asynchronous completion and startup/provider outcomes affect whether that alias exists. The packaged `extra/enable` and `extra/check50` settings are separate from `db_name`/`db_compressed`; no effective extra50 input or decryption relationship is established. [Path-origin evidence](../../project/review/firmware-analysis/remaining-firmware-run05-2026-11-01/packets/f450/REPORT.txt) preserves the distinction between declaration, request and actual filesystem state.

A BACnet application caller supplies a temporary Configuration pathname and relative template pathname to an opaque helper, whose returned word selects local return or logging/exit requests. Its semantic result, working directory, file contents and template activation are unresolved. [Resource-caller evidence](../../project/review/firmware-analysis/remaining-firmware-run06-2026-11-01/packets/f450/REPORT.txt) establishes argument flow, not a complete parser or BACnet configuration contract.

### F459: a shared-store request is not durable state

The selected shared-store constructor requests opening a database, a busy handler and creation of a table with `pluginname`, `key`, `value` and `persistent` fields. Its read/write methods use the same receiver's handle under normal object/provider premises.

| Operation | Selected source contract | Material limit |
| --- | --- | --- |
| Write | Supplied strings pass Latin1/Base64/ASCII conversions; supplied integer is formatted into the fourth `persistent` SQL placeholder | Accepted values, SQL success and durability are unproved; a retained earlier SQL result is tested after a later request |
| Read | Two-placeholder lookup; step result `100` selects column 0 text, byte-array construction, Base64 decoding and ASCII conversion into the supplied output | Actual rows, complete errors and lossless roundtrip are unproved; another selected branch stores an empty representation |
| Namespace source | External global-symbol address is dereferenced; a supplied field reaches assignment into the receiver's namespace string | Global definition, value, meaning, natural caller and uniqueness/isolation remain unresolved |
| Monitoring | Receiver-owned watcher requests file-path registration and connection to `_onChange` | Actual notifications, fresh data, connection success and callback lifetime remain unproved |
| Teardown | Normal selected path requests SQLite close before watcher destruction; deleting destructor uses the same receiver | The close result is overwritten before a later member comparison; actual close/commit, last-owner ordering and concurrent quiescence are unproved |

[Constructor](../../project/review/firmware-analysis/remaining-firmware-2026-11-01/packets/run01-f459/REPORT.txt), [write](../../project/review/firmware-analysis/remaining-firmware-2026-11-01/packets/run02-f459/REPORT.txt), [read](../../project/review/firmware-analysis/remaining-firmware-2026-11-01/packets/run03-f459/REPORT.txt), [namespace](../../project/review/firmware-analysis/remaining-firmware-run05-2026-11-01/packets/f459/REPORT.txt) and [teardown](../../project/review/firmware-analysis/remaining-firmware-run06-2026-11-01/packets/f459/REPORT.txt) records retain exact SQL, object roles and guards. The static-metadata getter has its own zero-state branch; the dynamic alternative remains opaque. This narrows a name/index relation without proving effective Qt binding, successful notification, callback behavior or database freshness. ### MH200N and F453AV: resource and module requests need their own environment

A selected MH200N startup path chooses retained resource pointers. Its reader requests a 1024-byte read and delimiter tokenization; a subsequent nonnull token reaches a compiled destination. Descriptor validity, terminated input, tokenizer state, destination capacity and ordinary providers remain prerequisites. No complete resource grammar, field meaning or installation outcome follows. [Resource source evidence](../../project/review/firmware-analysis/remaining-firmware-2026-11-01/packets/run03-mh200n/REPORT.txt) and [token destination](../../project/review/firmware-analysis/remaining-firmware-2026-11-01/packets/run04-mh200n/REPORT.txt) retain the bounded paths.

The separately packaged MH200N taskmanager formats a compiled `*.*.spt` pattern into a listing request, then a listing pathname into a file-open request. A selected nonnull stream/line path reads up to 80 bytes, obtains string length, writes zero to the last byte and passes the modified line to a filename formatter. The selected slice has no positive-length or newline-byte test; nonnull read does not prove a complete nonempty filename. Natural caller, capacity, actual files/stream contents and provider behavior remain unresolved. These requests do not establish accepted scenario grammar or a compiler. [Listing request](../../project/review/firmware-analysis/remaining-firmware-run07-2026-11-01/packets/mh200n/REPORT.txt) and [line consumer](../../project/review/firmware-analysis/remaining-firmware-run08-2026-11-01/packets/mh200n/REPORT.txt) preserve the source premises.

F453AV's normal startup selects its own module-load script; the recovery script differs even where selected module/loader bytes match. Loading, kernel compatibility, video readiness and ordering with application startup remain unresolved. Its separate recovery entry/resource gate does not transfer MH200N marker semantics or establish a valid descriptor, active partition or installation. [Module evidence](../../project/review/firmware-analysis/remaining-firmware-2026-11-01/packets/run02-f453av/REPORT.txt) and [recovery context](../../project/review/firmware-analysis/remaining-firmware-run06-2026-11-01/packets/f453av/REPORT.txt) retain those distinct image roles.

### F455: retain a format hypothesis without assigning a target

The raw payload is identified by wrapper/XML/CRC evidence. A finite vector-shaped pattern is compatible with a generic M-profile/Thumb interpretation, but does not establish actual CPU, ISA, endian encoding, ABI, base, load map or entry behavior. Authoritative product/image-linked loader, linker, debug or hardware evidence is needed before code interpretation. [Format evidence](../../project/review/firmware-analysis/remaining-firmware-2026-11-01/packets/run02-f455/REPORT.txt) and [provenance limits](../../project/review/firmware-analysis/remaining-firmware-run07-2026-11-01/packets/f455-gap/REPORT.txt) preserve the hypothesis without assigning a target or capability.

## Evidence limits and next work
