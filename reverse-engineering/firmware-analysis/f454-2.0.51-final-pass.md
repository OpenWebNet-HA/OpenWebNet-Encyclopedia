# F454 2.0.51 energy and video-status consumers

The old energy client and ordinary WHO 8 status route in F454 Firmware `2.0.51` have distinct input, state and termination rules. These source-derived rules complement the [protocol-to-client dataflow](f454-2.0.51-continuation.md); they are not captured exchanges or physical measurement results.

## Old energy frame to consumer

Selected `api-arm` DIM56 and DIM510 mappers preserve dimension/date text in JSON `date` and record identifier plus following values in string `extraValues`. They select dedicated hourly/daily old-device event names, consumed by the packaged energy model. This joins the [per-record producer](f454-2.0.51-continuation.md#old-format-energy-producer) to its client, independently of newer DIM511..514 and the direct-DH candidate.

| Consumer | Selected source behavior |
| --- | --- |
| DIM56 hourly | Match UI month/day; record 1 uses the second payload value; records 2..8 place three values each; record 9 places two values and a totalizer high byte; record 10 adds the second payload value as the low contribution |
| DIM510 daily | Match UI month; cases 1..21 reconstruct high/low byte pairs across records; no case 22 |

The F454 daily decoder zeroes individual `255` bytes before arithmetic. Hourly scalar fields use similar replacement, while the record 9 totalizer high byte is a separate unnormalized value. The [historical touchscreen decoder](../../functional/who-18-energy-management/dimensions.md#legacy-graph-values-and-unavailable-data) instead zeroes the complete `255*255` pair. Neither implementation establishes a universal wire sentinel or physical unit.

The hourly array begins with 24 zeros. The selected record sequence writes index 0 and indices 2..24, leaving index 1 at its initial zero and extending the array to 25 elements. That untouched zero is initialization, not a received zero measurement. A one-value terminal record 21 cannot supply all three values that daily case 21 reads, and a separate record 22 has no handler case. Actual stream length and calendar termination are therefore material prerequisites for a compatibility assessment.

The old handlers have no year gate. The daily model and graphic view also use different date-selector classes, so a model update need not prove a visible graphic update. Ordered-delivery host examples expose source consequences; they do not establish missing-packet recovery, browser rendering, live data loss or a physical defect. [Consumer evidence](../../project/review/firmware-analysis/f454-2.0.51/final-pass-energy-report.txt) and [explicit host examples](../../project/review/firmware-analysis/f454-2.0.51/final-pass-energy-model.json) retain the conditions.

## WHO 8 DIM35 ordinary role route

The inspected ordinary parser classifies `*#8**35##` as a measure request with WHO `8`, empty WHERE and DIM `35`. A selected `bt_vct` route reaches the role 1 handler, where empty WHERE uses a local branch rather than the addressed IP delegate.

Before the acknowledgement tail, mutable modes `1..3` retain the local acceptance flag for the selected measure request. Other modes with absent WHAT clear it and lead to rejection. The selected constructor initializes the mode to `-1`; actual later state matters. This establishes conditional ACK/KO paths for this role, not a DIM35 status-field formatter or the response seen by every client.

The frontend's split-index 4 condition belongs to a separate [answering-machine response producer](f454-2.0.51-av-and-board.md#video-status-response-ownership). Role selection, state transitions, factory media enablement and discovery remain separate. [Routing evidence](../../project/review/firmware-analysis/f454-2.0.51/final-pass-media-report.txt) preserves the parser and role guards.

## Evidence limits

These rules are specific to the identified F454 build. Reuse for another Firmware requires its own source identity and behavior evidence; matching names or similar code do not establish equivalence. Physical record counts/units, actual status exchanges, initial role activation and complete application state remain unresolved. The [source/review record](../../project/review/firmware-analysis/f454-2.0.51/final-pass-provenance.json) retains exact implementation locators and method limits.
