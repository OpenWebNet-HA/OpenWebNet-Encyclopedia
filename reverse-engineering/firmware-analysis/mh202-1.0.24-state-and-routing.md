# MH202 1.0.24 scenario state and routing

MH202 separates scenario scheduling, per-line script evaluation, functional translation, asynchronous receipts and diagnostics. This page describes the selected implementation contracts in Firmware `1.0.24`; the [build profile](mh202-1.0.24.md) identifies the package and components. Static source findings and isolated original-helper results are distinguished from complete runtime behavior. The public command meanings remain in the corresponding functional reference pages.

## Scenario execution and control

### Event matching and the configured panic frame

For the selected WHO `9` callback, WHERE `1..10`, a changed cached WHAT and readiness can reach trigger matching. A first-known value and an unchanged value have different paths. The outer handler clears trigger-hit fields; matching marks entries, and traversal clears each hit before invoking its stored callback with the script record. All matched entries are traversed on the selected path. This does not establish identical event policy for every family.

A full-frame comparison with `configuratore/setup/sicurezza/panic` sets the command gate and calls stop for scripts with nonzero control state. That gate also suppresses ordinary matching and WHO `17` normal commands. Working mode `4` can set the same gate, so its value is not unique evidence of a panic event. Gate clearing and the complete manual-described recovery procedure remain unresolved. [Event/control source](../../project/review/firmware-analysis/mh202-1.0.24/run2-functional-report.txt), [readiness and mode policy](../../project/review/firmware-analysis/mh202-1.0.24/run6-lifecycle-report.txt).

### Control state, FIFO messages and restoration

The interpreter and taskmanager communicate through internal FIFO commands. These are not additional WHO `17` wire operations.

| First byte | Selected receiver action |
| --- | --- |
| `S` | Set control state `2`, parse PID from payload offset `2`, with previous-state cleanup guards |
| `R` | Set control state `2` |
| `P` | Set control state `3` |
| `E` | Request cleanup and selected request-association clearing |
| `F` | Under length/global guards, parse supplied OPEN text and request handling; a qualifying result sets state `4` |

Nonzero control state includes pending, request, pause and stop states. The execution/control formatter therefore does not prove a live child. Concrete producers emit `S <pid>`, `F <text>` and `E`; dedicated `R`/`P` producers remain unresolved. Actual FIFO framing, delivery and child lifetime are separate questions.

Startup first restores saved state, then performs a distinct always-start pass. Saved-state mask `1` represents execution/control and mask `2` disabled state. Only saved-active records with `$RESTART=SI` are relaunched by restoration; the later pass tests inactive state and `SEMPRE`. Readiness and a once guard constrain both. Exhausting the initial query list establishes readiness even when a selected OK or KO path advances it; it does not prove positive data acquisition or a healthy service. Resetting that query cursor/readiness is separate from clearing the command gate. [Control and restoration evidence](../../project/review/firmware-analysis/mh202-1.0.24/run2-functional-report.txt), [readiness evidence](../../project/review/firmware-analysis/mh202-1.0.24/run6-lifecycle-report.txt).

### Saved-state file contract

The state file contains a `12`-byte header and `300` state bytes. Defaults use four magic bytes and state `0xff`. The writer marks header byte `4` as ASCII `1`, requests header/state writes, changes it to ASCII `0`, seeks back and requests the header again. Its selected writes, seek and close are not checked before local return `0`.

The reader checks the magic, then requests the state array. Marker `1` logs and converges on the same read rather than rejecting or rolling back. Both reads are unchecked in the selected body. Open failure or wrong magic selects defaults and a save request. These rules do not certify full I/O, crash recovery or durability. [Saved-state source](../../project/review/firmware-analysis/mh202-1.0.24/run4-lifecycle-report.txt).

### Action-level disablement and IPC producers

The selected `OWRITE` path checks a name-derived `DISABLED` marker. Stat result `0` returns integer `1` before constructing/writing its `F` request. A selected `OREAD` prefix reaches its first request without that same marker guard. The inspected trigger matcher, start callback and always-start pass do not themselves test the record's disabled field. This establishes path-specific action suppression, not universal start or all-action policy.

The taskmanager name derived from `$NOME` and the interpreter's exact ` $NOMESCRIPT` directive must denote the same runtime script for the marker join to hold. [Generated-script syntax](mh202-1.0.24-generated-scenarios.md) supplies a producer relation, but actual configured content, effective globals and installed paths remain premises.

An `=OWRITE` caller stores the helper's integer return; the standalone caller ignores it. Thus marker-skipped return `1` can become numeric data without command emission or action success. Named FIFO options and descriptor stores are described in the [record lifecycle](mh202-1.0.24-record-and-script-lifecycle.md#named-fifo-options-reach-descriptor-globals). [Action/IPC source](../../project/review/firmware-analysis/mh202-1.0.24/run3-functional-report.txt), [return-value source](../../project/review/firmware-analysis/mh202-1.0.24/run4-functional-report.txt).

## Script expressions and flow

### Interpreter conditional and operator spelling

The interpreter recognizes `IIF`, extracts operands through `PARENTESI` from source position `3`, and calls the IIF helper. That helper's integer return is unused; the interpreter continues testing ordinary instruction prefixes on the resulting line.

| Selected operation | Implementation contract |
| --- | --- |
| Ordinary operand extraction | Operator bytes `<`, `>` and `=` divide left and right text up to a comma; the ordinary unflagged path does not rewrite the line |
| Integer comparison | Operators `=`, `<`, `<=`, `>`, `>=`, `<>`; an unrecognized operator returns zero |
| Conditional continuation | The comparison selects one versus two comma-prefix removal requests on the shared line buffer |
| Numeric lookup | Name-based lookup-or-create initializes a new value to zero; assignment formats ID `1` as key `001`, while IIF uses stripped operand text directly |
| Local name distinction | `$V001` can select key `001`; `$V1` asks for a different name under the selected source/global premises |

The line-copy requests overlap. Isolated tests of the packaged copy helper corroborate particular supplied suffix copies, but do not give overlapping `strcpy` portable semantics or execute a complete IIF statement. Operand capacity, actual globals, string branches and complete configured grammar remain unresolved. The stored clock/calendar result becomes comparison data; it is not itself a Boolean action gate. [Interpreter source](../../project/review/firmware-analysis/mh202-1.0.24/run2-interpreter-report.txt), [operand extraction](../../project/review/firmware-analysis/mh202-1.0.24/run11-functional-report.txt), [numeric records](../../project/review/firmware-analysis/mh202-1.0.24/run10-functional-report.txt), [packaged copy tests](../../project/review/firmware-analysis/mh202-1.0.24/run8-strings-report.txt).

### Logical folding and GOTO

A selected two-clause OR path accumulates comparisons and rewrites the shared operands to a `0/1` left value, `=` and right value `1`. Parenthesized recursion shares those output buffers. OR and AND have separate seen flags but a shared accumulator/pending pair: first use of the other separator can replace the earlier accumulator, and selected OR finalization can leave a pending value that prevents the subsequent AND finalizer. These source relations are insufficient to publish a complete precedence specification or infer a configured-scene defect. [Logical folding](../../project/review/firmware-analysis/mh202-1.0.24/run12-functional-report.txt), [mixed separators](../../project/review/firmware-analysis/mh202-1.0.24/run13-functional-report.txt).

`GOTO` changes the shared current-node selection. A head match leaves the head selected; a successor match leaves its predecessor selected, after which the outer loop advances once and uses the next file offset. The concrete head is the [first BEGIN entry](mh202-1.0.24-record-and-script-lifecycle.md#the-script-head-is-the-begin-entry), so an arbitrary linked-list example cannot establish that the first action is skipped. A conditional delay path also resets `sleep_executed`; that is not a command-gate reset. Actual labels, list termination, files and configured flow remain unresolved. [GOTO source](../../project/review/firmware-analysis/mh202-1.0.24/run17-lifecycle-report.txt).

The ordinary comparator handles literal bytes and selected nonnegative bracket forms: comma lists, inclusive ranges and a negated number. Its single-member bracket path rejects that form. It can finish when either cursor is exhausted without a final equal-length test. Isolated original-helper tests corroborate these local results under modeled string/conversion providers; synthetic prefixes do not establish valid network frames or physical false triggers. The `130`-byte common fields are not the different `90`-byte libopen layout. ## COSO objects and routing

COSO translation, synchronizers and state machines are separate from the WHO `17` scheduler. Application and field dispatchers compare each descriptor's criteria with the record's WHO, call distinct callbacks and supply separate output-list locations. A coherent parsed WHO `0` record can therefore reach the scenario STM, without establishing accepted raw input or a natural transaction.

The installed publication callback is `sm_receive`; synchronizer output first routes toward state-machine field handling. An incrementing local helper supplies new record IDs. Existing-record conversion can preserve the source status/ID; the NULL-source path creates a fresh envelope and ID. A helper's returned list head is not a Boolean success value. The [record lifecycle](mh202-1.0.24-record-and-script-lifecycle.md) documents those object and publication distinctions. [Dispatcher/ID source](../../project/review/firmware-analysis/mh202-1.0.24/run7-functional-report.txt), [existing-record parser/helper test](../../project/review/firmware-analysis/mh202-1.0.24/run17-protocol-report.txt).

Selected original pointer-parser tests classify synthetic `*2*0*0##` as command kind `1` and `*#4*1*0##` as query kind `3`; serializing that same query object reproduces its text. These COSO kinds are separate from the C++ parser kinds and from private envelope routing, representation and status words. [Pointer parser/serializer evidence](../../project/review/firmware-analysis/mh202-1.0.24/run16-protocol-report.txt).

## Diagnostic translation and completion

### Parser providers and General-class selection

Static dependency/symbol models select candidate `libopen` parsing in `bt_device` and `libcommon` parsing in `openserver`, under packaged search paths and ordinary interposition assumptions. The objects and predicates are not interchangeable across these processes.

WHO `1000` is in the diagnostic-family mask but absent from the generic WHO-to-SCS map. Its General DIM `0` route has key `R0P0`, suffix `8C000100` and fixed header `$04`, yielding conditional internal candidate `$048C000100`. The selected WHERE registry has a present-null WHO `1000` entry: it performs no translation or result-structure writes. The selected General fixed-header route does not use those address fields. Normal-factory ownership resolves `R0P0` to General, but parsing, registry state and actual transport remain premises.

A second parse receives text traced to the original object's raw buffer. Null WHERE translation still leaves its local result marker untouched; a subsequent response-type-0/DIM-0 path consults that marker for collector mode `7/8`. The selected visible zero-fills do not cover it, but complete alias/callee writes and prior state are unresolved. No deterministic mode or uninitialized-memory defect is inferred. ### DIM1 data and object identity

A selected `19`-character internal path uses key `D2S80` for the General device-model member. ### Application progress markers

The daemon sweep skips stored launch result zero; other values, including `-1`, test a name-derived marker. Metadata success requests unlink; failure returns immediately. This does not test PID liveness, marker age or content. The `bt_supervisione` producer's configured path can match the consumer; it requests its marker before socket creation and after nonnegative waits. Interrupt and other negative-wait paths differ, so this is not fixed readiness or cadence.

A separate counter/flag gate reaches a watchdog helper; its requested operations and unchecked results do not establish driver acceptance, actual refresh/reset or a complete recovery policy. Low-level counter arithmetic and watchdog bytes remain in the supporting source record because they do not define an OpenWebNet interface. ## Evidence limits
