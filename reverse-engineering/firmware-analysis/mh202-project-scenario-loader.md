# MH202 ScenarioSuite project loading

ScenarioSuite has a local XML loader and a separate collection-based compiler. The actual caller connecting them remains unresolved. The selected loader retains the deserialized `cScenario` object in the same published container; this establishes an object-source contract without proving a configured project was successfully loaded or compiled.

The implementation belongs to the MyHOME Suite `3.5.38` installer assemblies associated with package `1902_1.0_LGG`. That applicability is separate from MH202 Firmware `1.0.24` and from any installed Configuration.

## File selection and collection publication

| Stage | Selected source behavior | Condition |
| --- | --- | --- |
| Loader dispatch | Numeric mode `0` selects `LoadscenariosMH202` with the supplied output slot | Actual receiver mode and natural caller remain unobserved |
| Collection metadata | Conditionally copy `ScenarioCollection.xml` and `info.xml` from the working directory to a temporary directory | File existence and ordinary copy/provider completion |
| Container creation | Publish a new `cScenariosCollection` through the supplied by-reference slot | Valid writable slot and normal constructor return |
| Scenario selection | Enumerate working subdirectories, request a folder copy and construct a corresponding `.xml` path | Actual directories, copy result and selected existence test |
| Object retention | Deserialize as `cScenario`, test nonnull and pass that same returned reference to the published container's collection `Add` | Successful serializer/type/provider path and preserved output reference |

The backing field is an `ObservableCollection<cScenario>`; the Core insertion call declares the base `Collection<cScenario>` owner. Their shared element type is established by each assembly's own metadata. A reference retained by this path does not itself establish lifetime, valid configured values or absence of later mutation.

## Relationship to compilation

The [ScenarioSuite generator](../../scenario-engine/scenario-suite-generator.md) accepts a scenario collection and constructs command/script output. Composing these sources requires an actual caller to pass the loader output to `CompileAll` without replacement or invalidation. That caller remains unresolved. File-copy requests, typed deserialization and source return codes do not certify a complete or nonempty project load.

Retained manufacturer default-project files provide XML structure and ZIP metadata, but no genuine populated scenario/export was admitted from them. Defaults are not a commissioned installation, and encrypted archive members do not supply known scenario contents.
