# MH202 1.0.24 functional translation and receipts

MH202 Firmware `1.0.24` uses distinct plugins for sound, alarm, transversal, special-command and CEN translation. Their routing criteria, parsed kinds, envelope fields and private state are separate namespaces. The [Firmware profile](mh202-1.0.24.md) identifies the build; the functional references remain canonical for published command meanings.

Translation and state relations below come from static source inspection. Explicitly identified parser/helper tests execute selected original code in isolated memory with supplied providers. Synthetic strings and internal bodies are not captures, accepted complete field transactions or Physical Device observations.

## Translation examples and direction

Each row starts from its own supplied coherent parsed or decoded input. A forward and reverse example do not establish a causal round trip.

Sound's forward wrapper copies ID but does not initialize the status field in the selected body; its reverse path copies status and ID. Source selection and field copies therefore do not establish accepted raw input, complete initialization, delivery or physical correlation.

## Multimedia query state and separate receipts

The multimedia state machine has its own private pending, ID, status and deadline storage, separate from the message envelope. A coherent ordinary-enabled, source/utility-disabled query can append the same record, store its ID and compute pending state. A supplied case with all fifteen checked status bytes `1` and zero deadlines returns before timeout-source creation. Other status/deadline state can take different paths, so this does not establish a timer-free policy for all queries.

A supplied receipt must match the saved ID and a nonzero pending flag for the selected receipt paths. Status `1` clears pending without the selected NACK/timer-destruction calls; status `2` clears pending, requests local NACK and conditionally destroys/unrefs a source. ID mismatch does not take those changes. A distinct parsed-kind-`4`/matching-DIM route can request timeout argument `1300`; it is not the selected ordinary query route. Timer delivery, complete producers, callback consumers and ownership remain unresolved. [Multimedia state source](../../project/review/firmware-analysis/mh202-1.0.24/run21-sound-report.txt).

### Utility deadline and restoration

Under utility enablement and coherent WHO `22` / kind `1` / WHAT `19` / WHERE `5` fields with null selectors/parameters, a selected path saves two state bytes, sets managed utility state and requests `send_util_state`. It then stores the entry-clock sample plus `600` in its deadline words. With a nonzero deadline, a clock strictly later than the deadline and the required managed state, `control_timeout` clears the deadline, restores the saved state, sets separate saved fields to `1/10` and makes another helper request. Equality does not restore.

The packaged GLib/libc source model computes `signed32(seconds) * 1000000 + signed32(subseconds)`. Under ordinary successful ARM32 `gettimeofday` ABI/provider assumptions, the increment is **600 microseconds**. The syscall result is not checked before copying, and the clock was sampled before the intervening helper; neither successful binding nor a measured delay is observed. [Deadline source](../../project/review/firmware-analysis/mh202-1.0.24/run23-sound-report.txt), [conditional clock units](../../project/review/firmware-analysis/mh202-1.0.24/run24-clock-report.txt).

Utility enablement can be supplied by a distinct parsed-kind-`5`, exact DIM-text-`15` application path. After local address checks, its tenth ordered value (zero-based `9`) is converted with decimal `strtol` and passed unchanged to the utility word. Missing/NULL tenth data supplies `0`; this is not Boolean normalization or a published wire count/range. Values `8/9` independently supply source/ordinary words, and optional value `11` defaults to `1`. The initializer's utility-zero default belongs to its own callsite; the later setter can satisfy the nonzero gate without establishing an admitted Configuration or natural event sequence. Its local ACK request does not certify initialization, persistence or physical activation. [Ordered-value consumer](../../project/review/firmware-analysis/mh202-1.0.24/run24-sound-report.txt).

## Conditional post decoded alarm routing

A supplied decoded category with body `00004209` classifies as record type `9`; the separate translation example supplies type `3`. Both satisfy the selected translator guard. That does not validate the body as real SCS traffic.

For criterion `4`, descriptor field value `2` permits an indirect field callback while value `1` skips it. That descriptor field is distinct from the record's representation field. Main installs `field_receive`; registration and private tuple storage establish a conditional same-userdata binding. The declared `scs_field_bus` and `scsai_field_bus` descriptor values are `1` and `2` respectively. Packaged `SCSAIEnable=1` controls optional parameter reads, while both registration requests occur on the subsequent common path. Actual module activation, ready field sources and same-userdata delivery remain unobserved. ## WHO 25 translation and state machine

The WHO `25` state machine maintains its own state, saved ID, timer source and publication callback. For coherent parsed/envelope/context state, kind `2` and a WHERE beginning with character `3` append the same query, save its ID, enter state `1` and request timeout argument `1000`. The local test does not require exact WHERE `3` and is not a complete address validator.

| Selected state/input | Local behavior |
| --- | --- |
| State `1`, matching ID/status `1` | Enter state `2`, forward and rearm |
| State `1`, matching ID/status `2` | Reset and request local NACK |
| State `1`, mismatching ID | Selected forward/rearm path remains possible |
| State `2` | Uses the forward/rearm path without the same ID comparison |
| Timeout state `1` / `2` | Construct software NACK / ACK, invoke the stored callback, then reset |

Forwarding appends the same field record and can also request constructor selector `4`; that selector is not parsed kind `4` or a receipt. Reset clears state/source, sets saved ID to `0xffffffff` and requests source destruction when present. Kind `1` has a separate local WHAT mask `11..15,21..28,31,32`, not a gateway-wide support table. Full cancellation, correlation, reference ownership and elapsed scheduling remain unresolved. [WHO 25 state-machine source](../../project/review/firmware-analysis/mh202-1.0.24/run25-stm-report.txt).

### Original query object entering the state machine

An isolated original-code test constructs synthetic `*#25*312##`, producing WHO `25`, WHERE `312`, query kind `2` and NULL WHAT/DIM. The driver manually passes the same object through the original initializer and application callback. The selected callback changes envelope metadata, saves the generated ID/state and appends that same query while requesting a timer. Parsed fields are not reseeded. Opaque supplied timer/context handles and a NULL publication callback leave the real framework, timer, registry, translator and physical transaction unexecuted. [Query-object evidence and preserved identity refinement](../../project/review/firmware-analysis/mh202-1.0.24/run27-native-report.txt).

### Source destruction and ownership remain separate

The timer source's reference counter and the plugin's source pointer belong to different objects. Packaged creation initializes a reference, attachment adds one, active attached destruction requests a decrement, and unattached destruction instead clears an active flag. Explicit unref and other framework paths also change references. The plugin's destroy-and-clear/reset calls therefore establish neither zero release nor complete deallocation. A closed illustrative count omitting other owners/framework activity is not a leak or actual lifetime observation. [Source/caller ownership](../../project/review/firmware-analysis/mh202-1.0.24/run28-source-ownership-report.txt).

The [WHO 25 reference](../../functional/who-25-transversal/) preserves ScenarioPlus, CEN+, dry-contact/IR and ZigBee variants. Firmware-local masks, prefix checks, state and selected text symmetry do not merge their address/parameter models or redefine published meanings.

## WHO 14 special commands and WHO 15 CEN

WHO `14` and WHO `15` register separate descriptors and state policies. Each has reverse routing criterion `1`, distinct from forward criteria `14/15` and from OPEN WHO `1`.

| Plugin | Selected local state policy | Limit |
| --- | --- | --- |
| WHO `14` | Own pending/ID storage; ordinary command appends the same record, while a selected non-command path can store pending/ID without appending | Matching pending ID/status `1/2` requests ACK/NACK and clears pending, but a mismatch field may forward without clearing |
| WHO `14` timer scope | No timer requested in the complete selected callbacks | Does not establish whole-framework timing or lifetime |
| WHO `15` | Initializer returns `0` without allocating private context; kind `1` / WHAT `5` / parameter `2` appends the same record and requests local ACK; parameter `8` has a different NACK branch | Additional parameter and signed/unsigned guards are source predicates, not an expanded button or press-duration specification |
| WHO `15` field path | Marks its metadata for monitor forwarding and forwards the same field record without saved-ID/timer testing in that complete callback | Does not establish natural event admission or successful output |

The [WHO 14](../../functional/who-14-special-commands/) and [WHO 15](../../functional/who-15-cen/) references retain their attributed public meanings and grammars. Selected source constructions and local receipts do not certify physical lock, button or phase behavior. [WHO 14 source](../../project/review/firmware-analysis/mh202-1.0.24/run26-who14-report.txt), [WHO 15 source](../../project/review/firmware-analysis/mh202-1.0.24/run26-who15-report.txt).

## WHO 29 plugin and selected read

`libplug_debug.so` registers criterion `29`, binds an application callback and explicitly checks parsed WHO text `29`. This establishes a packaged owner path under module-loading and outer-callback premises, without establishing a loaded instance or exclusive ownership.

One supplied WHERE `4` / kind `3` / DIM `2` read requests `get_log_type`. A supplied getter result `0` leads to formatted value `1`, an output-list request and local software ACK. The numeric constructor arguments and eventual wire/object representation remain unclassified. Actual logger state, other debug commands, access paths and a public WHO `29` vocabulary are not inferred. The selected initializer and field callback return `0`.
