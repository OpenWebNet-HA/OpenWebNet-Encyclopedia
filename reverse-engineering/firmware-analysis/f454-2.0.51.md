# F454 2.0.51 implementation

F454 Firmware `2.0.51` contains distinct OpenWebNet diagnostic, scenario, alarm and video components. The implementation findings below apply to this exact build of the [audio/video web server and gateway](../../devices/definitions/own-dev-0002-audio-video-web-server-gateway.md). They supplement the published protocol and product documentation; they do not describe every installed Configuration.

## Build composition

The build targets TI DaVinci DM365/BASI and ARM926T/ARMv5 with ARM EABI. These are kernel build declarations, not a hardware interrogation. Normal and recovery images retain separate data and startup environments even where executable code sections match.

Packaged defaults, volatile runtime files and persistent user Configuration are separate sources. The root is configured read-only, while a writable persistent partition supplies extra/configuration storage. Its live contents are absent from the package. Consequently, packaged service declarations and defaults do not identify installed activation or current runtime state. [Platform evidence](../../project/review/firmware-analysis/f454-2.0.51/platform-report.txt) retains the underlying image and build details.

## Selected execution boundaries

These results come from synthetic offline fixtures using identified original helpers, not captured traffic.

| Selected path | Result under the recorded fixture | Material boundary |
| --- | --- | --- |
| Scenario sender | Write results `-1` or `0` request close/reset, skip the second write and reach both output destructors/free requests, while the sender returns `0`; a short-positive result is accepted without tail retry | Descriptor, non-SSL I/O and allocation/free behavior are supplied; delivery and actual reclamation are unproved |

## Source reconciliation

The package label does not create a new catalogue Firmware record. Product documentation remains authoritative for connector roles and supported physical arrangements; the inspected binaries establish only their own scoped software behavior. Existing [WHO 25 gateway observations](../../project/review/who25-gateway-compatibility.md) are separate evidence.

Unresolved matters include persistent/optional assets, active provider and subscription setup, complete transport recovery, configured scenario behavior, exception and thread lifetime, installation authenticity/durability, and the physical meanings or production of selected temperature and energy values. The relevant pages state narrower resolved and unresolved relationships beside each claim.

## Alarm and AV applicability

F454 has a separately packaged SCSAI/COSOAI software lane and distinct video-status/mode owners. Those software links do not by themselves establish electrical terminal wiring, natural serial-origin admission or active camera service. See [alarm/AV ownership](f454-2.0.51-product-paths.md) and [video-status ownership](f454-2.0.51-av-and-board.md).
