# Curated IR inputs

`canonical-sources.jsonl` is the closed classification list for every Markdown page in the eight canonical documentation areas. It deliberately contains no `guides/` entries. The source gate rejects a newly added canonical page until it is classified here. A `sanitize` entry is reviewed source policy, not permission to include raw private material. Private captures, logs, inventories, and exports never belong in this manifest as publishable inputs.

`identities.json` maps each canonical path and heading anchor to a durable document or section ID. Its initial allocation was reviewed and committed once. On a move or heading rename, update the mapping key while retaining its ID. Never run `--bootstrap-identities` in routine builds. If a section changes meaning, curate a new identity and retain lifecycle history. OpenWebNet Machine KB 0.1.0 establishes the first public ID compatibility baseline; the registry's `first_release` metadata records that lifecycle origin.

`reference-records.json` is the reviewed semantic input for canonical namespaces, glossary terms, entities, relationships, cautions, open questions, and selected public evidence sources. It stores stable IDs and canonical section IDs, not copied source paths or independent source documents. The build resolves those sections through the shared IR, inherits their public or sanitized privacy metadata, generates record provenance, and fails if a referenced section no longer exists. Canonical-document source records are generated directly from the IR and are not duplicated in this input.

`claim-records.json` contains the reviewed atomic assertions and opaque claim IDs used to generate the current 7,449-claim candidate. Each claim records its subject entity, namespace, exact section ID and pinned prepared-section SHA-256, evidence class and public source where applicable, status, scope, value, cautions, questions, and typed claim links. To revise a section, review its affected assertions against the new source before updating the digest; never refresh all pins automatically as a routine build step. The generator joins the seed to the same IR used by all other artifacts and rejects stale sections, missing references, and asymmetric contradictions.

`claim-coverage.json` accounts for every section in the bounded canonical claim domains as either claimed or explicitly reviewed non-claim material. The build rejects stale or inconsistent coverage.

The guide remediation check emits path and line only, without copying guide text or adding it to the IR. Release-readiness review adjudicated the current 183 hints with no additional canonical promotion required. Rerun and adjudicate the queue after future guide changes; heuristic flags can include false positives, and an empty hint list does not certify complete coverage.
